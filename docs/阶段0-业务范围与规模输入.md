| 卡务与账户 | 账户/卡状态、冻结解冻、余额和账户账本由账户服务负责 | [微服务划分](微服务划分.md) |

## 2. 规模输入

项目文档不要求填写个人或部门责任方。容量数字记录统计时段和来源；没有数据时保留“待确认”，不据此设置生产 TPS 或容量结论。

| 输入项 | 当前值 | 状态/所需证据 |
|---|---:|---|
| 组织/租户数、实施站点数 | 待确认 | 项目范围、合同资料待补 |
| 持卡用户数、有效卡数及增长率 | 发卡人数 8,000；有效卡口径、增长率及该数字对应的统计日期/规划阶段待确认 | 用户提供；待卡务台账核对并标注统计日期 |
| 消费终端数及型号/协议分布 | 终端合计约 150 台；消费终端数量、型号/协议待确认 | 用户提供约数；需设备资产台账核对 |
| 门禁控制器/门数及型号分布 | 门禁约 100 台；门数、型号/协议待确认 | 用户提供约数；需门禁资产台账核对 |
| 日交易量 | 约 16,000 笔；交易类型拆分、典型/峰值日期口径和统计周期待确认 | 用户提供；待明确数据来源和覆盖业务 |
| 业务高峰窗口的在线交易峰值 | 约 200–800 笔/分钟（分钟均值约 3.3–13.3 笔/秒） | 午餐高峰小时内按 1 分钟滑动窗口估算；方法为高峰小时交易量 × 峰值集中度 5%–10%。方法和集中度为用户提供的估算口径，不代表已核实历史实测；峰值适用范围及交易类型待确认；此项不填写负责人 |
| 在线拒绝/超时率及下游延迟 | 待确认 | 现有平台指标或试点采样；无现网时标为未知 |
| 最长计划/可接受断线时长 | 待确认 | 结合资金风险、终端能力和离线额度模型确定 |
| 终端断线后的积压笔数与恢复时限 | 待确认 | 由最长断线时长和交易峰值推导，再经设备联测验证 |
| 每日门禁事件量、消息量和增长率 | 待确认 | 控制器/事件统计或一期目标估算 |
| 日结数据规模与允许完成窗口 | 待确认 | 结合清结算批次和结算约定确定 |
| 支付渠道限额、回调峰值、退款比例 | 待确认 | 渠道合同、商户后台或沙箱资料 |
| 个人/消费/通行数据留存周期 | 待确认 | 结合数据目的、适用规则和专业评估结果确定 |

## 3. 测试环境基线

| 环境 | 资源 | 用途和限制 |
|---|---|---|
| 本地开发机 | Windows 11 x64；Ryzen 7 5800H；15.86 GiB 可见内存；16 个逻辑处理器 | 第一轮构建、测试和本地依赖 PoC；结果只代表本机 |
| Maven 实际 JVM | Maven Wrapper 将 `JAVA_HOME` 指向 Oracle JDK 25.0.4.1；当前 shell 的 `java` 命令报告 Temurin 25.0.5 | 每份报告记录 `mvnw --version` 的 JVM；后续统一入口，避免仅凭 `java -version` 误报 |
| 开发测试服务器 | 用户提供：16 GB 内存；当前 SSH 端口连接超时 | 连通后再采集 CPU、OS、磁盘、JDK、Docker 版本及空闲资源，并在本地验证通过后部署复测；报告不得外推到生产 |
| 生产目标环境 | 尚未提供；真实业务环境预计大于当前开发测试资源 | 生产 OS/CPU/JDK 发行版适配和容量预算暂缓；生产服务器确定/更换后必须重新做兼容和容量测试 |

服务器凭据不写入本仓库或测试报告。部署顺序固定为“本地构建/测试通过 -> 开发服务器部署 -> 服务器端复测”；服务器测试失败时保留本地可运行状态，并记录环境差异及日志。
