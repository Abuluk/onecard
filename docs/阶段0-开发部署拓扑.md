# 阶段 0：开发部署拓扑

**状态**：本地拓扑已实测；开发服务器拓扑为部署前草案；生产拓扑延期  
**约束**：先本地验证，通过后才部署 16 GB 开发服务器；所有地址、密钥和凭据由各自环境提供，不进入版本库

## 1. 当前本地开发拓扑

```text
Windows 11 开发机
├─ Maven Wrapper / 本机 Java 进程：构建、单服务启动与本地冒烟
└─ Docker Desktop Compose（仅开发/监控验证）
   ├─ Gateway 127.0.0.1:8081
   ├─ 8 个业务服务 127.0.0.1:8082-8089
   ├─ Nightingale 127.0.0.1:17000
   ├─ GreptimeDB 127.0.0.1:4000
   ├─ Categraf
   └─ MySQL + Redis（仅供 Nightingale）
```

Compose 将 Gateway、业务服务、Nightingale 和 GreptimeDB 的宿主端口绑定到回环地址；MySQL/Redis 没有宿主机映射。当前 Compose 为 `test` profile，服务注册发现关闭或未依赖 Nacos；其 MySQL/Redis 不能作为业务数据组件 PoC。Nacos、OceanBase、Valkey 和 RocketMQ 尚未在本地栈运行。

## 2. 16 GB 开发服务器验证拓扑草案

```text
本地开发机
  └─ 本地构建/自动化测试通过
       └─ 传输本轮构建产物与测试配置（不传凭据）
            └─ 16 GB 开发测试服务器
                 ├─ 业务测试栈：应用服务 + 已批准的 Nacos/数据库/缓存/消息
                 ├─ 内部容器网络：服务间调用与数据组件
                 ├─ Gateway：仅开发测试访问路径
                 ├─ 管理面：仅受控运维网络访问
                 └─ 指标/日志采集：按环境单独配置
```

该拓扑是验证边界建议，不是已部署状态。开发服务器当前 SSH 连接超时，OS/CPU/JDK/Docker/磁盘资源、网络区和现有服务均未采集；此处没有进行远端变更。恢复连接后，先只读盘点，再确定部署目录、端口和资源限额，并保持用户现有服务/数据不受影响。

网络约束草案：

- Gateway 是普通客户端 API 的唯一入口；设备协议入口走设备接入边界，不能经普通用户路由获得信任。
- 风控、设备内部 API、Nacos、数据库、缓存、消息、Actuator 和监控管理面不得默认暴露到外网。
- 具体公网、设备、内部服务和管理网段/ACL 尚未提供，不能以 Compose 的 loopback 绑定推断远端安全边界。
- Gateway 与 8 个服务均静态配置 `spring.config.import`：dev 以 `optional:nacos:` 导入 `${spring.application.name}.yaml`，prod 以必需 `nacos:` 导入同一 DataId；两者均使用 `DEFAULT_GROUP`，基础地址由 `NACOS_SERVER_ADDR` 注入。`test` 禁用 Nacos 配置和发现，Gateway 的 `compose` profile 使用显式路由。当前未设置 namespace、认证/TLS 或敏感配置加密；具体值仍待开发拓扑决策。静态配置一致性已核对，目标版本运行态导入和发现尚未验证。

## 3. 生产目标环境

生产 OS、CPU、JDK 发行版及实际拓扑暂不具备，按已确认范围延期。真实业务服务器预计大于当前测试资源；生产部署前重新确定兼容矩阵、网络分区、副本、存储、备份/恢复、监控和容量预算，不由本机或 16 GB 开发服务器结果外推。

## 4. 验证与运维待决项

- 目标软件组件的精确版本、镜像摘要、配置导入、注册发现、数据库/缓存/消息 PoC。
- 内外部端口清单、服务身份、设备认证、管理员访问路径和防火墙规则。
- 开发/测试 Secret 注入、证书签发/吊销、日志脱敏和环境配置权限。
- 业务数据库备份/恢复、消息持久化/保留、离线 WAL 与门禁快照恢复。
- RTO/RPO、日结窗口、监控告警与升级/回滚步骤；等待实际数据和业务约束后确定。
