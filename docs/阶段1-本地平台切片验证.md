## Nacos 与服务发现

- 固定镜像：`docker.1panel.live/nacos/nacos-server:v3.1.1@sha256:13e74786507abbacebe080fae2fc9c05aa2591eb99c97a0a78ff0e72beb21b13`。
- Compose 将 Nacos 设为 standalone；镜像要求 `NACOS_AUTH_TOKEN` 即使在关闭 Nacos 鉴权时也必须提供。本地通过被忽略的 `.env` 注入，CI 冒烟每次生成临时 token。
- Nacos Console、HTTP API 和 gRPC 端口没有映射到宿主机；服务通过 Compose 私网访问。开发 Compose 关闭 Nacos 身份鉴权，只适用于该隔离网络，不可作为生产配置。
- Gateway 和八个服务使用 `dev` profile 启动；九个实例均健康注册在 `DEFAULT_GROUP`。Gateway 的 `lb://onecard-account-service` 路由能将请求转发到账户服务；测试路径因当前服务骨架没有业务 API 而返回服务端 HTTP 404。
- Nacos readiness 探针通过。重启 Nacos 后再次达到健康状态，账户服务实例自动恢复注册。
- 直接访问账户服务 `/actuator/health` 返回 `UP`。现有 k6 脚本对该端点运行 1 VU、10 秒：10 个请求、20/20 checks 通过、HTTP 错误率 0%、p95 9.54 ms。此结果仅是启动健康冒烟，不代表网关、业务负载或容量表现。
- Nacos 远程配置导入、动态刷新、必需配置缺失、认证/TLS、故障重连时长和其他中间件尚未在本次切片验证。

## 复现

```powershell
./mvnw.cmd --batch-mode --no-transfer-progress clean verify
if (Test-Path .env) { throw 'Keep the existing .env and update its Nacos token manually.' }
$token = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
@(
  "NACOS_AUTH_TOKEN=$token"
  "NACOS_AUTH_IDENTITY_KEY=serverIdentity"
  "NACOS_AUTH_IDENTITY_VALUE=onecard-local"
) | Set-Content .env -Encoding ascii
docker compose -f deploy/monitoring/docker-compose.yml config --quiet
docker compose -f deploy/monitoring/docker-compose.yml up --build
```

启动完整栈前需完成 `.env` 生成步骤；不要提交 `.env`。Nacos 配置缺少 token 时 Compose 应失败并提示补齐环境值。
