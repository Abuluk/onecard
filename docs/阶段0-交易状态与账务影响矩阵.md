# 阶段 0：交易状态与账务影响矩阵

**状态**：开发基线；幂等、离线触发和恢复屏障 PoC 规则已暂定；生产额度及设备/账务故障测试待完成
**依据**：项目确认在线优先、仅意外断线触发终端故障切换；服务写入边界见 [`微服务划分.md`](微服务划分.md)

本表记录已采用的开发资金规则和仍需验证的边界；不代表生产限额已确定。账户资金操作使用稳定 `operation_id`，同键同摘要返回原状态/结果，同键不同摘要冲突；离线流水唯一键暂定 `(tenant_id, terminal_id, local_seq_no)`，64 位终端序号先持久化。资金幂等引用按项目策略保留约 15 年；法律适用性另行核验。

|---|---|---|---|---|---|

## 首期资金路径与退款/对账归属

| 资金路径 | 成功时资金影响 | 退款/冲正 | 对账归属 |
|---|---|---|---|
| 聚合渠道充值到校园卡账户 | 经渠道成功状态核验后，通过账户服务契约幂等增加校园卡余额并记录充值账本分录 | 按原聚合渠道及合同处理；同时校验可退余额，不能把已消费余额当作仍可退款资金 | 渠道充值单与账户充值分录逐笔核对 |
| 校园卡余额刷卡消费（主路径） | 账户服务本地事务扣减余额并记消费账本分录 | 在校园卡账户产生关联原消费的反向账务分录，不改写原分录 | 终端流水、交易记录与账户账本核对 |
| 聚合渠道直接消费 | 外部渠道确认收款并记录独立的直付交易状态；不增加校园卡账户余额 | 按原外部渠道退款，退款状态与账户储值退款分开跟踪 | 聚合渠道消费单与直付交易记录核对 |

三条路径在交易、资金来源、幂等键、退款状态和对账明细中必须可区分。不得将聚合直付消费误记为校园卡充值，也不得将充值成功直接认作消费成功。渠道合同和沙箱未核验前，以上为业务/账务设计规则，不代表通道已经具备相应产品能力。详见 [ADR-0007](adr/0007-campus-stored-value-and-aggregator-boundary.md)。

## 必须保持的不变量

- 余额与账户账本在账户服务本地事务内一致提交；交易、支付、清结算和终端不能直接写账户表。
- 一个幂等业务交易最多产生一次有效扣款效果；超时、重复回调或补传不能产生第二次入账。
- 明确业务拒绝不触发离线支付；结果未知不转成本地成功。
- 终端离线受理、平台入账和客户可用余额是不同状态，API 与提示不得把“本地已落盘”误报为“平台已确认入账”。
- 每笔允许离线受理的消费都必须对应平台已签发、已从可用余额扣减的额度；未预留额度不得离线受理。
- 待复核、风控不可用或账务状态未知时，相关预留不得释放；拒绝结果必须通过独立、可审计的补偿/冲正收敛。
- 恢复在线模式前，终端进入 `RECOVERING`：查询未知在线请求、按序号幂等补传、确认连续高水位、同步余额/预留额后恢复在线；恢复期间不重新开启离线。设备与账务故障测试待做。

## 阶段 0 后续验证项

1. 离线预留额度按卡/终端分配、到期回收和撤销的可实现性。
2. 未知在线请求与后续新离线交易并存时，预留额度如何避免双重占用。
3. 设备接受离线交易后拒绝/冲正时，依据渠道和商户合同确定最终资金归属；原流水不得删除。
4. 重复/缺号/乱序/终端序号回退时的账务处置和审计证据。
5. 退款、撤销、部分成功和支付渠道争议的账本语义。
6. 恢复屏障步骤、交易/账务状态保留期以及终端提示的硬件联测。

本矩阵的采用方向与公开参考见 [ADR-0003](adr/0003-offline-payment-reserve-and-review.md)。
