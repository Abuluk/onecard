## 2. Nacos 配置导入静态核对

Gateway 与 8 个业务服务均按以下方式配置：

| Profile | 导入策略 | DataId / Group | 结论 |
|---|---|---|---|
| `dev` | `optional:nacos:` | `${spring.application.name}.yaml` / `DEFAULT_GROUP` | Nacos 暂不可用时允许开发服务启动；客户端仍会重试，需留意日志 |
| `prod` | `nacos:`（必需） | `${spring.application.name}.yaml` / `DEFAULT_GROUP` | 配置缺失或 Nacos 不可用应阻止启动，须通过目标版本实测 |
| `test` | 不导入 Nacos；关闭配置与服务发现 | 无 | 隔离单测，不作为 Nacos 集成证据 |
| Gateway `compose` | 仅声明本地显式服务路由 | 无 | 与 `test` profile 配合，不依赖 Nacos 服务发现 |
| 当前本地 Compose | 应用使用 `dev` profile 并连接 Nacos；基础 Compose 文件不自带 DataId | 见 dev 行 | 新 BOM 联测临时写入九个 DataId 并检查 metadata，九应用注册、Nacos 重启恢复和 Gateway 发现路由通过；2026-11-12 account 使用 Nacos 3.3.0 Pure client 对 Server 3.1.1 完成配置导入和 2 秒内热刷新；prod 行为仍未验证 |

9 个应用的 `spring.application.name` 均与服务名一致，基础地址由 `NACOS_SERVER_ADDR` 注入，缺省为 `127.0.0.1:8848`。2026-11-02 至 2026-11-03 使用 Nacos 3.1.1 amd64 临时单节点，端口只绑定 `127.0.0.1`。九个新构建 JAR 分别使用 `dev` profile，从各自 `${spring.application.name}.yaml` / `DEFAULT_GROUP` 加载远程端口配置，健康端点返回 `UP`，Nacos 实例列表均显示对应端口的健康实例。Gateway 另通过临时 `lb://onecard-account-service` 路由访问账户服务 `/actuator/health`，返回 HTTP 200。验证后已逐个停止应用，并删除临时 Nacos 容器。

旧版运行态结果覆盖 Boot 4.1.2 / Cloud 2025.1.4 / Alibaba 2025.1.0.0 下九个应用的 dev 配置导入和注册，现仅作为历史记录。2026-11-03 新 BOM Compose 复测中，九个应用各自导入临时 Nacos DataId 标记并健康注册；逐个重启后 metadata 标记仍在；Nacos 容器重启后九个实例重新健康注册，Gateway 的服务发现路由到达账户服务（骨架服务对转发的 actuator 路径返回预期 404）。这证明本地基础链路在官方对应 BOM 下运行，不覆盖 prod 必需导入失败、配置变更刷新、Nacos HA、认证/TLS、主机故障或监控抓取。临时测试关闭 Nacos 认证并清理了容器及新建数据卷。

运行态发现：8848 上的 `/nacos/v1/console/health/readiness` 返回 410 并提示迁移到 v3 路径；Nacos 3.1.1 的 Console 实际监听 8080，访问 `http://<nacos-host>:8080/v3/console/health/readiness` 和 `/v3/console/health/liveness` 返回 200、`{"code":0,"message":"success","data":"ok"}`。将 v3 路径错误地加上 `/nacos` 前缀或访问 8848 会得到 404。`/nacos/v1/ns/operator/metrics` 返回 `{"status":"UP"}`。后续健康检查应从容器网络访问 8080 的 v3 readiness 路径；8080 是 Console 管理面，不应公开到外网。

## 3. 决策与验证顺序

1. 使用官方版本表列出的 Boot 4.0.0 / Cloud 2025.1.0 / Alibaba 2025.1.0.0；本地 Nacos 配置导入、注册发现和 Gateway 路由复测已通过。
2. 锁定开发基线中的框架、Nacos、数据库、缓存和消息组件具体版本；禁止以 `latest` 代替版本记录。
3. 本地先运行全量 Maven 构建和测试，再执行数据库迁移/事务、缓存并发/故障、消息重复/乱序/恢复等 PoC。
4. 本地通过后再部署至 16 GB 开发服务器复测。2026-11-03 SSH 已连通，完成只读资源盘点和 OceanBase/Flyway 基础 PoC；完整应用栈和故障/性能复测仍待安排。
5. 生产 OS/CPU/JDK 发行版和生产容量目标按用户决定延期；目标生产环境具备后重新核验，不由本地或开发服务器结果推断。
