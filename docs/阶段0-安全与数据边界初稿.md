# 阶段 0：安全与数据边界初稿

**状态**：评审草案；OIDC 与 `realm_access.roles` 数组路径已选且 Keycloak PoC 通过；阶段 1 已增加开发态 Gateway 资源服务器，但正式身份提供方/audience/角色值、数据分级、合规适用性及现场门禁行为尚未批准
**范围**：外部入口、信任边界、数据类别和待验证威胁，不包含生产认证实现或正式法律/测评结论

## 1. 信任边界与入口暴露

| 调用方/边界 | 设计入口 | 期望边界 | 当前发现/未决项 |
|---|---|---|---|
| 用户端、管理端 | API Gateway | 按角色与资源授权；管理操作与普通查询分离 | 已选 OIDC；`https://xxx` 是脱敏占位符；Keycloak 26.8.1 PoC 确认 `realm_access.roles` 是字符串数组；正式身份提供方、API audience、角色值、权限映射及 CORS 来源待确认；PoC 默认 `aud=account` 不用于一卡通配置，见 [ADR-0004](adr/0004-oidc-user-and-admin-identity.md) |
| 支付渠道 | Payment Adapter callback ingress | 首期微信/支付宝/云闪付聚合回调专用验签、时间戳/nonce 防重放、按渠道幂等；实体校园卡走平台交易链路 | 聚合服务提供方、回调域名/端口、证书和最终渠道协议/合同未确定 |
| 消费/门禁设备 | Device Service 独立设备接入边界 | 设备身份、协议 allowlist、隔离网络；不得靠普通用户路由鉴权 | 设备协议、证书生命周期及现网网络段未知 |
| 内部服务 | API 契约/消息通道 | 服务身份、最小权限、内部网络访问控制 | 服务间认证、同步/异步通道和消息授权未实现/未验证 |
| 人员主数据源 | Access Service 集成 | 只读/受控同步、明确撤权时限，不由门禁服务成为未授权权威源 | 权威系统和接口未知 |
| 运维与基础设施 | Nacos、数据库、消息、Actuator、监控管理面 | 仅管理网络/VPN/堡垒机可达，凭据按环境注入 | 生产拓扑未定；本地 Compose 仅绑定回环地址不能代表生产网络控制 |

阶段 0 基线检查时 Gateway `application.yml` 曾定义 8 组路由，其中包含 `/api/risk/**` 和 `/api/devices/**`，尚无安全配置。截至阶段 1 开发切片，风险、设备和二期 access 路径已从 Gateway 移除，并增加开发态 OIDC JWT 验签、默认拒绝、角色授权、身份头清理和独立管理端口。相关实现与测试见[Gateway 入口白名单](阶段1-Gateway入口白名单.md)。这不代表正式 IdP、生产授权矩阵、共享限流或生产网络隔离已验收。

OIDC 只适用于用户/管理员身份方向。Keycloak PoC 已确认 `realm_access.roles` 为字符串数组；Gateway 自动化测试使用临时 RSA/JWKS stub 覆盖签名、issuer、audience、过期时间和角色不足。Keycloak 客户端配置导出、正式 issuer/audience/角色映射、真实 IdP 联测以及服务与设备身份仍待单独完成。

## 2. 数据类别与待定控制

下表只列出项目方案涉及或可能涉及的数据类别，不分配法定/正式安全等级。

| 数据类别 | 业务用途 | 最小化/访问建议 | 尚待确定 |
|---|---|---|---|
| 账户、卡介质标识、余额和账本 | 消费扣款、账户查询、差错处理 | 账户服务写入；最小字段返回；敏感标识不进普通日志 | 卡号表示/脱敏、余额查询授权；交易流水在线 5 年、归档后再保留 10 年的用户策略尚待适用性/审计核验 |
| 人员身份信息 | 用户/员工与卡、门组关系 | 仅同步鉴权和业务必需字段；访问记录可追溯 | 人员主数据源、字段、同步/撤权 SLA、保存期限 |
| 消费、充值、退款及支付回调 | 资金处理、客户查询、对账 | 签名/幂等、防重放；与账本对账；渠道凭据隔离 | 渠道清单、合同、商户数据范围、回调和退款周期 |
| 通行事件与门禁权限 | 现场授权、通行审计 | 按门组/岗位授权查看；记录撤权与人工处置 | 通行记录目的、保留/删除期、跨系统共享范围 |
| 生物特征或核验数据 | 门禁与核验为二期扩展；若二期启用刷脸/人证核验再单独评估 | 未经单独批准不采集/留存生物模板；日志中不记录模板或原始图像 | 二期是否启用、供应商处理方式、保存位置/时长和评估要求 |
| 设备密钥、终端证书、离线 WAL | 设备认证、离线受理与安全补传 | 密钥不可明文写入普通配置/日志；终端存储完整性、备份/恢复需验证 | 密钥托管、签发/吊销、轮换、终端丢失与本地擦除机制 |
| 管理审计、安全日志和指标 | 追责、诊断、告警 | 记录主体/动作/结果，不记录密码、令牌和完整敏感标识；指标避免个人标签 | 事件字段、不可篡改要求、访问角色、留存和删除周期 |

用户指定交易流水在线保留 5 年、归档后再保留 10 年（约 15 年总周期）。该周期作为项目留存策略输入记录；反洗钱法是否直接适用于系统运营主体及该业务数据、法定起算点、归档可检索性和删除/冻结要求仍须法律与审计评估。不得将此用户策略表述为适用于所有校园卡平台的普遍法定最低期限。正式分类分级、主体权利流程及密码应用范围也保持未决。

## 3. 威胁场景清单

| 威胁 | 关键场景 | 当前控制方向 | 验证状态 |
|---|---|---|---|
| 冒充/提权 | 伪造终端、普通用户访问风险/设备/清算管理路由、内部服务伪装 | 设备身份、服务身份、路由 allowlist、资源级授权 | 未实现/未验证 |
| 篡改/重放 | 重复支付回调、修改离线流水或序号、重放门禁命令 | 签名验签、nonce/时效、幂等键、序号与本地持久化校验 | 仅为设计要求 |
| 抵赖 | 人工冲正、清分规则修改、终端离线消费确认缺少证据 | 独立审计主体、审批链、交易/设备事件关联 | 审批与留存未定 |
| 信息泄露 | 手机号/卡号/通行记录进入日志、监控标签或管理面 | 数据最小化、脱敏、凭据隔离、监控基数控制 | 代码与配置尚未全量审查 |
| 拒绝服务 | 午餐窗口流量、回调洪峰、离线补传挤占消费通道 | 超时、限流、队列隔离、背压和恢复测试 | 四站点并发压力输入已记录；旧 16,000 笔/日输入已作废，实际交易曲线仍待台账核实 |
| 越权/破坏 | 修改余额、卡状态、门禁策略、Nacos 配置或账户数据库 | 权限分离、服务数据权属、管理网络隔离、变更审计 | 目标架构与部署验证未完成 |

## 4. 合规与现场安全边界

- 当前方案标题和部分章节曾把“等保三级”写成已确定要求；阶段 0 的主计划仍将系统定级、等保/密评和产品认证适用性列为待确认。基础方案已调整为候选控制草案，不据此宣称定级或通过测评。
- 是否启用生物特征、目标数据分类、留存/删除要求，须结合业务目的和适用地区评审；本文件不作法律结论。
- 门禁断电、断网、快照过期、人员撤权、消防联动及紧急疏散行为须按实际门型和控制器验证，不采用对全部门型统一的 fail-open/fail-closed 结论。

## 5. 阶段 0 下一步验收

- 按 [ADR-0004](adr/0004-oidc-user-and-admin-identity.md) 选择正式 IdP 并补齐 issuer、audience、令牌类型、角色值和权限映射；另行确定设备/服务的身份源、认证、授权、撤权和审计边界。
