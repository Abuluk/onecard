| 用户与卡主数据 | 学校现有学籍/人事/卡务主数据源作为权威源；一卡通系统保存带来源标记的副本，不反向改写权威字段。首期以稳定的外部人员 ID 和卡介质 ID 做映射，不把卡号作为 OIDC 用户名。 | 实际系统名称、字段、同步方式、注销/冻结时限和冲突责任人。阶段 1 先定义适配契约，不接真实上游。 |
| 首期路径 | 三条路径独立建模：聚合充值到账户、校园卡余额消费、聚合渠道直接消费；单笔只允许一个资金来源，不做拆分支付或跨来源自动补差。充值后刷卡是主要消费路径。 | 聚合服务合同是否同时支持充值与直接消费，及其商户/结算主体。 |
| 日常业务量 | 旧 16,000 笔/日不再用于容量估算。实际日交易量、小时曲线和日结批次均留空，不从设计峰值反推业务预测。 | 试点/历史台账；取得后更新负载模型。 |
| 交易比例样本 | 压测数据暂按消费 90%、充值/补助 8%、退款/冲正 1.9%、查询/其他 0.1% 生成；该样本满足已确认的比例边界，不是业务预测。 | 接口分类和真实台账；有实际分布后替换样本。 |
| 峰值模型 | 四站点同时各 800 笔/分钟，即全平台 3,200 笔/分钟、约 53.3 笔/秒；连续 30 分钟为 96,000 笔。JMeter 满载 10 分钟为最低阶段性样本，30 分钟为完整设计压力场景。 | 真实交易 API 落地后测量；测试结果只对记录的环境和版本有效。 |

## 资金、离线与恢复默认

| 项目 | 暂定方案 | 待外部验证/不能默认开启的部分 |
|---|---|---|
| API 幂等 | 每个资金写操作要求调用方提供稳定幂等键。服务保存规范化请求摘要；同键同摘要返回首次操作状态/结果，同键不同摘要返回冲突（HTTP 409）。账户余额、不可变账本、操作结果和 outbox 在账户服务一个本地事务中提交。 | 真实 API/数据库并发与崩溃测试；外部渠道是否支持幂等键另按合同验证。 |
| 去重保留 | 资金操作唯一引用与账本同生命周期保留；依照已确认的“在线 5 年、归档后再保留 10 年”项目策略，在 15 年保留期内不得删除仍可能重放的幂等引用。归档后仍可按引用查询/拒绝重复操作。 | 法定适用性、归档可检索性、删除例外和最终保留期由校方审计/法律评估。该期限是项目输入，不作为法律结论。 |
| 离线补传键 | 使用 `(tenant_id, terminal_id, local_seq_no)` 唯一约束；终端为每台设备持久化单调递增的 64 位序号。服务端保存载荷摘要。同键同摘要返回既有结果；同键不同摘要进入安全告警/人工处置，不覆盖原交易。缺号可暂存后等待补齐，重复号按幂等结果处理，乱序不改变账务顺序。 | 终端协议、重装/换主板后的序号续接、设备身份和批量补传测试。 |
| 离线额度 | 每笔限额、每卡日累计限额、每终端日累计限额均配置化。签名额度租约和终端名单快照的 PoC 有效期最多覆盖 3 个就餐日，过期即拒绝离线支付；缺少有效策略或额度值为零时同样失败关闭。开发测试使用隔离的非真实额度。 | 校方风险/财务批准具体金额、名单刷新策略、逾期行为和超额人工流程前，生产离线消费必须保持关闭；三日断网内的撤卡/冻结传播风险需明确接受。 |
| 离线触发 | PoC 默认仅把传输层连接失败/超时计入链路故障：连续 3 次失败且发生在 5 秒窗口内后标记 `DEGRADED`。业务拒绝、鉴权拒绝、风控拒绝和渠道明确失败不触发离线。结果未知的原请求保持待确认并沿用原幂等键；只有之后的新交易可按有效额度离线受理。阈值只作可配置测试默认。 | 设备协议、食堂网络测量、终端 UI 提示和 3 个就餐日断网演练。不得把该阈值表述为行业基准。 |
| 恢复屏障 | 终端先停止新的离线受理并进入 `RECOVERING`；使用原键查询所有未知在线请求；按终端序号补传并取得服务端确认；核对连续高水位、账户余额与预留额度；完成状态刷新后才回到 `ONLINE`。恢复期间在线请求可以继续，但若再次断网不得回退离线，直到屏障通过。任何缺号、内容摘要冲突或未决资金操作都会阻止该终端恢复离线能力并产生告警。 | 终端 WAL 持久化/损坏、补传乱序、长时间积压、账户争用与设备重启故障注入。 |
| 流水容量 | 按用户输入每终端 100,000 条和每终端 800 笔/日计算，3 个就餐日为 2,400 条，占记录数容量 2.4%；100,000/800=125 个平均交易日。此算术不覆盖单条大小、索引/WAL 开销、峰值分布或闪存寿命。白名单目标为至少 20,000 张。 | 厂商确认可用存储、掉电写入原子性、满盘行为和真实设备测试。 |
| 可靠推进 | 不引入 Seata/XA 作为默认。账户服务本地事务写 outbox；发布采用至少一次，消费者以事件 ID 幂等。暂定退避为 1s、2s、5s、10s、30s，此后带抖动按最高 60s 间隔持续重试；超时/毒消息转人工告警队列，不丢弃、不伪报成功。 | RocketMQ Spring 客户端集成、重复/乱序、死信、长时间不可用和积压清空演练。 |
| 数据库故障目标 | RPO=0 只承诺在明确演练的一种数据库切换场景内，对调用方已确认成功的资金操作逐笔无丢失、无重复；未确认操作必须可查询并收敛。恢复点之外的主机/存储/异地故障不自动包含在内。 | 目标数据库集群拓扑、确认语义、切换前后账本/余额/幂等对账及恢复时间演练。RTO 暂不设生产值。 |

## 身份与支付默认

| 项目 | 暂定方案 | 待外部验证/部署限制 |
|---|---|---|
| OIDC 模板 | 使用 Keycloak 作为开发验证 IdP。容器网络内 issuer 模板为 `http://keycloak:8080/realms/onecard-dev`，本机浏览器访问可映射到 `http://127.0.0.1:<port>/realms/onecard-dev`；API audience 暂定 `onecard-api`。原始 `https://xxx` 是脱敏占位，不是可部署 issuer。 | 生产 issuer、TLS、realm、客户端 ID、audience 及密钥轮换由部署环境配置。 |
| 角色边界 | 保留 `realm_access.roles` 字符串数组。开发角色暂定 `onecard-user`、`onecard-admin`、`onecard-auditor`；默认拒绝未声明角色。客户端 `fullScopeAllowed=false`，授权策略 `ENFORCING`，只显式授予 API 所需角色。 | 校方授权矩阵和实际角色名称；不把示例角色写成用户已确认的生产权限。 |
| 授权负向用例 | 预期无效签名、issuer 不匹配、audience 不匹配、过期令牌均返回 401；签名有效但缺少资源角色返回 403。测试需由资源服务器实际执行并保存配置导出、用例和日志。 | 当前服务尚无资源服务器/业务 API，因此这些用例仍未执行。Keycloak claim 结构 PoC 不能替代它们。 |
| 终端身份 | 消费设备不复用师生 OIDC 角色；默认每台设备独立凭证并可单独吊销，服务端按 `terminal_id` 授权。生产优先使用设备证书/mTLS；若硬件不支持，由设备厂商提供可轮换、可吊销的等效方案。 | 终端安全芯片/证书能力、批量发证/吊销和网关透传方式。 |
| 支付接入 | 默认使用一个聚合支付适配边界承接微信、支付宝、云闪付；分别保存渠道交易号、资金来源、回调状态、退款状态和对账结果。聚合充值成功后才向账户服务幂等入账；直付消费不增加校园卡余额。 | 聚合服务合同、是否支持三渠道与直接消费、商户关系、分账/直连、验签、回调重放、退款和结算能力。未有合同前不声称渠道 PoC 通过。 |
| 清结算 | 项目目标仍为 T+1 自动对账、原路径退款、24 小时冲正目标和签约渠道支持范围内的 T+0/T+1 结算。渠道实际规则不支持时进入差异/人工处理，不静默改为其他资金路径。 | 合同、账单样例、时区/节假日、部分成功与 24 小时起算规则。 |

## 软件与验证默认

1. 数据库开发基线沿用 OceanBase 4.4.2 LTS MySQL 模式与 Flyway；阶段 1 首个应用集成用标准 JDBC API，迁移脚本只经 Flyway 管理。除非 JDBC PoC 显示明确不足，本阶段不新增 ORM 依赖。该选择须通过 Spring 应用连接、事务、唯一约束、并发和迁移恢复测试后才算关闭。
2. 数据库迁移按四阶段执行：评估（语法/数据/回滚范围）、预演（副本迁移和一致性扫描）、切换（停写/增量追平/切换点确认）、验证（逐表计数与关键资金字段对账、观察和回退窗口）。`T/BFIA 009` 原文、版本和适用范围未核验，当前不把它作为验收依据。信创迁移项目再增加至少一个完整业务周期双轨观察。
3. 阶段 1 开发模型按一个租户、8,000 人、4 个站点、四站点同步 3,200 笔/分钟设计；生成数据覆盖余额倾斜、重复键、未知结果、退款和离线补传。真实日量/增长率未知，不据此配置生产规格。
4. 业务 API 可压测后，JMeter 阶梯为 50、100、250、500 并发；按共享吞吐控制器将总到达率控制在 3,200 笔/分钟，500 并发至少持续 10 分钟，目标场景持续 30 分钟。记录全局和各资金路径 P50/P95/P99、吞吐、错误、余额/账本一致性、CPU/内存/GC、连接池/锁等待及故障期行为。满载 10 分钟只关闭最低样本，不代表完整 30 分钟压力通过。
5. 当前仓库没有资金 API，JMeter 未安装。因此先完成基线构建与现有中间件/骨架 PoC；不为无业务接口的健康端点生成虚假的资金容量结论。JMeter 本身及真实业务负载测试安排在 API 和测试环境可运行后。
6. 项目留存策略是在线 5 年、归档后再保留 10 年，按交易日起算约 15 年总周期。日志默认只保留可排障的脱敏字段；原始渠道回调仅在受控证据存储保管，仓库保存脱敏副本/摘要。个人信息分类、加密方案、正式法律依据和归档删除流程仍需专业评估。

## 阶段门状态

- **阶段 0 临时结项口径**：本方案和相关 ADR 的缺失项已有默认决策；当前 Maven 全量构建、9 个应用 Nacos 联测及 Valkey、RocketMQ、OceanBase/Flyway 窄范围 PoC 记录构成开发基线证据。阶段 0 可以按“临时开发基线通过”结项，任务清单中的设计任务视为完成。
- **支付渠道暂行替代**：阶段 1 仅基于版本化、供应商中立的支付适配契约和本地模拟渠道开展开发；模拟器需覆盖签名回调、重复/乱序、回调丢失、退款和账单差异。微信/支付宝/云闪付真实沙箱、合同、云验收和结算模式属于真实渠道启用门禁；门禁未通过不发起真实收款或退款。
- **OIDC 暂行替代**：阶段 1 使用本文 Keycloak 开发模板、`fullScopeAllowed=false`、`ENFORCING`、固定 audience 和默认拒绝角色规则；任何对外受保护 API 开放前，必须完成资源服务器五条负向用例和授权矩阵。当前 claim PoC 不等同这些测试已通过。
- **资金与 RPO 暂行替代**：阶段 1 账户实现必须先通过同键重复 8 次、同键异摘要冲突、提交后丢响应、回调丢失、长款识别、服务重启及账本对账测试。真实数据库 HA 切换 RPO=0 尚无证据；在目标拓扑实测通过前，数据库故障时停止/拒绝资金写入，不自动切到可能丢失已确认写入的异步副本。
- **数据库暂行替代**：采用 OceanBase MySQL 模式 + Spring JDBC + Flyway。阶段 0 已有 OceanBase/Flyway 基础 SQL PoC；Spring 应用连接/事务、迁移扫描与恢复对账作为阶段 1 第一项平台集成门禁，在其通过前账户资金接口不得对外发布。
- **容量暂行替代**：保留 3,200 笔/分钟和 30 分钟 96,000 笔为目标。当前以现有 k6 工具替代未安装的 JMeter，先对隔离参考 API/组件切片验证测试脚本与报告格式；真实资金 API 完成后，必须完成 50/100/250/500 并发阶梯、至少 10 分钟满载及 30 分钟设计场景。模拟器或健康端点数据不得宣称为业务/生产容量。
- **安全与隐私暂行边界**：终端离线功能默认关闭、额度默认零；门禁/核验属二期。15 年是项目留存设计输入，待校方审计/法律评估，不作为法定最低期限。无正式数据分类、真实主数据源或专业合规结论时使用最小化测试数据、默认拒绝和脱敏日志。
- **阶段 1 可开展范围**：契约/DTO、服务内部骨架、模拟支付、账户账本原型、报告查询、测试基础设施及本地技术集成。真实通道接入、生产 OIDC 绑定、终端离线启用、生产容量承诺及 HA 自动切换必须满足相应门禁。
- 法律/标准状态：保留 15 年作为项目留存策略；当前未核验其为法定最低期限。关于 2026 年反洗钱新规及 `T/BFIA 009` 的公开来源查询未能完成，不将其写成合规或标准依据。
