# 阶段 0：负载模型与 SLO 基线

**状态**：初始业务输入已记录；请求结构待补；生产 SLO 暂缓  
**适用范围**：先用于本地/16 GB 开发服务器的可复测容量测试，不代表生产容量承诺

## 1. 已知规模输入

| 输入 | 当前值 | 解释与限制 |
|---|---:|---|
| 发卡人数 | 8,000 | 用户提供；有效卡数、统计时点和增长量未拆分 |
| 终端总量 | 约 150 台 | 用户提供；消费终端型号/数量分布待明确 |
| 门禁终端 | 约 100 台 | 属于约 150 台终端中的门禁类；门/控制器具体分布待资产清单 |
| 日交易量 | 约 16,000 笔 | 交易种类和日期口径未拆分，不能据此推导均匀负载 |
| 午餐高峰窗口 | 1 小时内的 1 分钟滑动窗口 | 用户明确的统计窗口 |
| 峰值估算方法 | 高峰小时交易量 × 峰值集中度 5%–10% | 用户提供的估算方法；目前没有单独给出午餐高峰小时原始总量，也未称为历史实测 |
| 估算峰值 | 约 200–800 笔/分钟 | 折算为分钟均匀平均约 3.3–13.3 笔/秒；窗口内瞬时到达形状未知 |

按用户要求，阶段文档不填写个人或部门责任方。负载口径和估算方法保留；不由估算范围反推未提供的午餐小时总量。

## 2. 开发验证档位

| 场景 | 目标输入 | 用途 | 通过/报告口径 |
|---|---:|---|---|
| 低档参考 | 200 笔/分钟（约 3.3 笔/秒） | 冒烟后的业务链路持续性和基础资源采样 | 记录吞吐、延迟、超时/5xx、资源和账务不变量 |
| 峰值参考 | 800 笔/分钟（约 13.3 笔/秒） | 1 分钟滑动窗口的初始峰值能力验证 | 记录每个滚动窗口实际完成量、错误、延迟分位数和资源；不能只看平均 RPS |
| 长时间窗口 | 午餐峰值小时 | 待获得小时总量/曲线、交易类型比例后建立 | 现阶段不生成合成曲线，也不把 800 笔/分钟假设为持续一小时 |
| 交易日批量 | 约 16,000 笔/日 | 后续清结算/日结批次测试输入 | 批次完成时限与日内分布未定；不能据日均值替代峰值在线负载 |
| 故障与恢复 | 离线消费、重复/乱序补传和服务恢复 | 检查幂等、资金一致性、队列积压与恢复 | 最长离线时间、积压规模和恢复时限未定，不给出虚构恢复 SLA |

完整业务曲线还需确定峰值是全平台还是单站点、消费/充值/退款等请求比例、交易 payload、重试行为和真实高峰小时总量。业务 API 尚未实现；当前 k6 脚本仅测 Actuator 健康，不得用于声称达到上述交易档位。

## 3. 测量项与验收边界

每次本地或服务器测试记录相同环境信息，并至少输出：

- 实际到达率、完成率和每个 1 分钟滚动窗口的最大完成量。
- p50/p95/p99 延迟、超时、连接错误、HTTP 5xx 与业务拒绝；业务拒绝和平台技术错误分开统计。
- 交易/账户账本一致性、幂等重复结果、离线序号缺口、补传队列积压和清空时间。
- CPU、内存、JVM/GC、线程与连接池、数据库锁/慢查询、缓存命中/错误及消息积压。
- 完整命令、代码版本、镜像/依赖版本、测试数据、日志及原始报告。

现阶段不指定生产 p95/p99、错误预算、逐服务资源上限、最大增长规模或 RTO/RPO。若接口实现前先做 stub/平台 PoC，报告只能说明该 PoC 在已记录开发资源上的结果。真实 API 落地后，至少按 200/min 与 800/min 两个输入档位测试；资金链路必须同时证明无重复入账、无漏失和账户/交易状态可收敛。

仓库 k6 通用模板当前给出错误率低于 1%、关键接口 p95 低于 500 ms、checks 成功率高于 99% 的默认阈值。这些值目前是脚手架约定，不是已批准的交易接口开发 SLO 或生产 SLO；健康端点冒烟结果也不能代替交易链路验收。进入阶段 1 性能门禁前，须按接口类型和业务拒绝语义批准开发环境阈值，并同步更新测试脚本/阶段报告。

## 4. 环境顺序与容量声明

1. 本地构建、现有测试和启动验证通过后，才尝试远端开发服务器测试。
2. 当前本地宿主机可见内存约 15.86 GiB；后续瞬时可用内存约 3.75 GiB，Docker VM 上限约 7.68 GiB。现有容器瞬时汇总约 3.0 GiB；新增 PoC 前需重新采样。
3. 开发服务器仅确认 16 GB 内存。SSH 连接超时，CPU、OS、磁盘、JDK、Docker 和空闲资源仍未采集；服务器未部署本轮产物。
4. 任何本地或 16 GB 开发服务器结果仅用于开发比较。生产资源更换或目标平台确定后，必须按实测业务负载重新做容量与恢复测试。
