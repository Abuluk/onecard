## 结论摘要

阶段 0 的决策任务已按[待确认事项与暂定方案](阶段0-待确认事项与暂定方案.md)完成处置：缺少事实采用保守默认，不能安全默认的功能设为关闭，并将真实验证转成阶段 1/生产启用门禁。已有框架构建和 Nacos、Valkey、RocketMQ、OceanBase/Flyway 窄范围 PoC 记录。支付业务区分聚合充值、校园卡余额消费和聚合渠道直接消费，主消费路径为充值到账户后刷卡；见 [ADR-0007](adr/0007-campus-stored-value-and-aggregator-boundary.md)。账户本地原子账务与跨服务可靠推进方向见 [ADR-0008](adr/0008-idempotent-account-operations-and-reliable-progression.md)。

本结论允许阶段 1 在模拟支付、默认拒绝未授权访问、离线额度为零和数据库故障时停止资金写入等约束下开发；不允许真实渠道收款/退款、生产离线消费、未经负向测试的对外受保护 API、未经目标 HA 测试的自动故障切换，也不构成法务/审计或生产容量批准。原始外部证据状态继续见[矩阵](阶段0-阻断点关闭证据矩阵.md)。

[阶段 0 阻断点重定义与推荐方案](阶段%200%20阻断点重定义与推荐方案.md)已按当前三类资金路径复核；其未附一手出处的行业指标、法律/标准适用性和产品主张不作为验收或合规结论。

## 检查点

- **A 业务、资金和数据责任：临时通过。** 业务范围、组织/资金模型、未知项和模拟渠道替代已定；真实渠道/账务 API 验证为启用门禁。
- **B 身份、安全和合规边界：临时通过。** OIDC 模板、默认拒绝、最小化与法务评估路径已定；真实授权测试及合规结论为 API/上线门禁。
- **C 开发技术基线、拓扑和容量：临时通过。** 已有 BOM/中间件 PoC；JDBC 应用集成和业务压测在对应平台/API 可运行后执行，生产容量继续延期。
- **D 联合验证与复核：临时通过。** 已有测试可复现，未取得的故障/安全/性能证据都已隔离为禁止启用条件，未冒充测试通过。

## 阶段 1 / 生产启用门禁

1. 真实微信/支付宝/云闪付合同、沙箱/云验收、回调验签和清结算模式通过前，支付适配器只连接模拟器，不允许真实资金操作。
2. OIDC issuer/audience/角色配置及五条资源服务器负向测试完成前，相关 API 不得公网/用户网开放；默认拒绝访问。
3. 账户 API 幂等×8、同键异摘要冲突、提交后丢响应、回调丢失、长款识别和账本对账通过前，不发布可用资金写接口。
4. OceanBase Spring JDBC/Flyway 集成、迁移预演/回滚和一致性核对通过前，不将账户服务作为可部署应用；目标切换场景 RPO=0 逐笔证明通过前，不启用自动 HA 资金写切换，故障时 fail closed。
5. 真实业务 API 的 k6/JMeter 阶梯、P99、账务一致性和故障期报告完成前，不声明达到 3,200 笔/分钟，不将健康/模拟器结果外推为业务容量。
6. 人员/卡数据源、留存分类和法规适用性由学校完成确认；门禁/核验维持二期范围及真实设备生命安全前置测试。

上述是阶段 1 实施与生产启用门禁，不撤销阶段 0 临时结项。实际原始证据状态仍在[阻断点证据矩阵](阶段0-阻断点关闭证据矩阵.md)维护；任何门禁失败时保持功能关闭，不降低账务、安全或容量验收标准。
