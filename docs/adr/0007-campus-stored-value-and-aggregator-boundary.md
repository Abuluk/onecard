# ADR-0007：校园卡储值与外部聚合支付边界

**状态**：已接受为首期业务模型；具体聚合服务和上线商户配置待合同确认  
**日期**：2026-11-03

## 背景

用户确认首期同时支持学校自发行实体校园卡，以及微信、支付宝、云闪付聚合支付；主要消费方式为聚合充值到账户后刷校园卡，聚合渠道也可以直接完成消费。此前“校园卡是校内封闭储值子账本”的假设不能用来概括带外部聚合支付的整个系统。

## 决策

1. 把校园卡账户余额视为平台管理的储值账本。校园卡自身不按银行发行卡建模；本决策不对整个平台是否适用支付、预付卡或教育收费法规作法律结论。
2. 首期区分三类业务资金路径：聚合渠道充值入校园卡账户、校园卡余额消费、聚合渠道直接消费。主要消费路径为前两类组成的“充值后刷卡”；微信、支付宝等聚合渠道直接消费也在已确认范围内，实际可用通道按聚合服务合同配置。
3. 首期按单一资金来源记录每笔交易。校园卡余额交易与外部直接支付分别记录来源、状态、幂等键、退款结果和对账明细；拆分支付和跨路径自动补差不在当前已确认范围内，如需支持应复审本 ADR。
4. 聚合充值只有在经过签名/状态校验的成功回调或主动查询确认后，才可通过账户服务契约幂等入账。结果未知时保持待确认，使用同一业务操作标识查询/重试，不重复发放余额。
5. 校园卡余额消费只在账户服务本地账务事务中扣款；直接聚合消费记录外部支付状态，不因此增减校园卡余额。两条路径均进入交易与清结算视图，但来源账本不可混写。
6. 校园卡余额消费退款以原校园卡账户的反向账务分录返还；聚合渠道直接消费退款走原外部渠道；充值退款按聚合渠道契约与可退余额规则执行。冲正 24 小时和 T+1/T+0/T+1 仍是用户确认的项目目标，具体起算、部分成功和渠道能力待合同验证。
7. 聚合服务合同、外部商户/结算主体、支付回调、退款和账单格式是外部聚合路径的实现前置。校园卡不是银行卡 BIN 卡，不代表整个系统不需要外部渠道合同，也不据此推定法律豁免。

## 备选方案

- 仅支持校园卡储值与刷卡：无法满足已确认的微信、支付宝和云闪付范围；不采用。
- 所有路径共用一个“支付成功”状态并统一写账户余额：会把外部直接支付误作校园卡储值，退款和对账也无法准确还原资金来源；不采用。
- 分别建模储值、校园卡余额消费和外部直接消费：采用；状态、资金权威源与清结算输入可逐笔追踪。

## 后果

- 交易 API 和报表必须区分充值、校园卡余额消费、外部直接消费及对应退款/冲正。
- 账户服务只记校园卡账户资金变化；外部直接消费由支付适配与交易状态记录，不伪造校园卡账本变更。
- 聚合支付产品、商户主体、回调/退款/结算语义仍由合同和上线范围确认；未具备合同/沙箱前不得声称该链路已验收。
- 校园卡储值子账本的法律定性及系统整体的支付/预付卡/教育收费适用性须由正式法规依据和学校财务制度评估，不能由本 ADR 推断。

## 复审条件

聚合渠道合同或沙箱与本模型不符；支付资金来源、直接聚合消费范围或校内商户结算主体改变；正式法律/财务评估改变业务边界时复审。

## 依据

首期卡介质、聚合渠道、主要充值后刷卡路径以及允许直接聚合消费均为 2026-11-03 用户确认的项目输入。适用法律条文、渠道合同和学校财务制度尚未作为本决策的外部证据。
