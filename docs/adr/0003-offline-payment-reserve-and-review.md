# ADR-0003：离线消费的预留额度与待复核资金处理

**状态**：采用为开发基线；数值限额和现场设备行为仍需验证  
**日期**：2026-11-02

## 背景

本项目以在线消费为常态，仅在意外断线时允许终端故障切换。终端一旦离线受理并完成本地持久化，服务端之后的风险复核不能静默删除该笔交易，也不能因服务端余额仍是旧值而再次开放同一笔资金。

截至 2026-11-02 可核验的公开参考包括 BIS 的 Project Polaris 离线 CBDC 支付手册，以及欧洲央行 2026-07-02 发布的数字欧元规则手册 v0.91 草案。后者包含 acceptance device、end-to-end process flows 与 settlement 技术附件；ECB 当前项目说明也包含离线钱包支付和钱包持有限额方向。这些是可借鉴的离线支付模式，不是本项目的法规或产品要求。

## 决策

1. 在线交易仍是唯一默认模式。余额不足、卡冻结、风控拒绝等确定业务结果不触发离线；在线请求结果未知时保持 `PENDING_CONFIRMATION` 并沿用原幂等键，不将同一请求转为离线成功。
2. 账户服务在线签发有限离线预留额度，将其从可用余额中扣除。额度绑定卡/终端，带版本、有效期及金额/笔数限制；未获得有效预留额度的终端不得离线受理。具体数值由设备联测和负载模型确定，不在当前阶段臆造。
3. 断线故障切换期间，仅后续新交易可消费端侧已签发额度。终端先持久化交易、单调序号和幂等键，再显示“离线消费已受理，联网对账中”；不得显示为平台已完成记账。
4. 服务端按原幂等键持久化补传流水。风控通过时，账户服务在本地事务中正式记账并结清对应预留额度；重复补传返回原状态，不产生第二次账务效果。
5. 风控结果为需复核，或风险服务暂不可用时，交易进入 `NEED_REVIEW` / 待处理状态，预留额度继续占用且不返还可用余额。风险服务恢复后可重试；任何待处理流水均不得静默丢弃。
6. 复核通过后，原交易转为已记账并原子结清预留。复核拒绝时保留原交易，以独立、可审计的补偿/冲正流水结束；在客户、商户和渠道资金结果尚未收敛前，不得释放对应预留。
7. 恢复在线前，终端与平台必须完成未知在线交易查询、离线流水按序补传、重复/缺口处理、账户预留结清和额度版本同步。恢复屏障未通过时，继续使用受限策略，不按旧余额恢复普通在线扣款。

## 状态与账务影响

| 阶段 | 交易状态 | 账户可用额/账本 | 终端反馈 |
|---|---|---|---|
| 在线签发离线额度 | `RESERVED` | 从可用余额转入离线预留；总账不丢失 | 显示当前额度/有效期 |
| 终端离线受理并落盘 | `OFFLINE_ACCEPTED` | 继续占用预留，不再释放给在线交易 | 离线消费已受理，联网对账中 |
| 补传且风控通过 | `POSTED` | 原子扣账并结清本笔预留 | 平台已确认 |
| 待复核/风险服务不可用 | `NEED_REVIEW` | 预留保持占用；可用额不增加 | 平台复核中 |
| 复核通过 | `POSTED` | 记账并结清预留 | 平台已确认 |
| 复核拒绝 | `COMPENSATING` -> 明确终态 | 通过补偿/冲正及对账收敛；收敛前不释放预留 | 显示复核结果及后续处理状态 |

## 不变量

- 终端离线受理的累计金额和笔数不得超过该卡/终端当前有效预留额度。
- 在线可用余额必须扣除未结清离线预留；交易服务和终端不得直接改账户余额。
- 一笔离线业务只产生一次有效记账；预留结清与记账必须具备原子性或可恢复的幂等状态机。
- 平台不确定、风险服务不可用、序号缺口或复核未完结时，采取保留/隔离，不以超时等同拒绝或成功。
- 已向终端确认受理的流水不能删除；拒绝/补偿必须引用原交易并保留审计证据。

## 验证要求

- 测试多终端争抢同一张卡额度、预留过期/撤销、终端重复/乱序/缺号、服务端已记账但响应丢失、风险服务不可用、复核通过/拒绝和补偿失败恢复。
- 验证在线可用余额、预留余额、终端剩余额度和账户分录逐笔守恒；资金状态未收敛时不能越过恢复屏障。
- 对终端掉电、WAL 损坏、密钥/凭据吊销和缓存过期执行设备级故障测试。
- 200/min 与 800/min 负载下采集交易尾延迟、错误、账务一致性、队列积压和预留额度更新开销；不把健康端点测试当作业务性能证据。

## 未决边界

离线额度金额、最长离线时长、缓存有效期、断线识别阈值、商户结算后的拒绝责任及补偿路径仍需结合终端协议、渠道合同和设备测试确定。文档不要求填写个人或部门责任方；服务级数据写入边界仍按 `docs/微服务划分.md` 执行。
