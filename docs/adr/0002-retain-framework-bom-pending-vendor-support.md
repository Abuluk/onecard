# ADR-0002：暂时保留当前框架 BOM 并等待供应商支持依据

**状态**：临时决定；官方兼容性待确认，联合验证部分完成
**日期**：2026-11-02；验证记录更新于 2026-11-03

## 背景

当前根 `pom.xml` 使用 Spring Boot 4.1.2、Spring Cloud 2025.1.4 和 Spring Cloud Alibaba 2025.1.0.0。Spring Cloud Alibaba 官方 2025.x 版本说明把 Alibaba 2025.1.0.0 对应到 Spring Cloud 2025.1.0 和 Spring Boot 4.0.0。当前 POM 组合没有被该表列为对应组合。

本地 Maven 全量构建和账户服务启动已通过，但这只说明当前代码在本地构建并能启动，不能证明 Alibaba 组件组合获得官方支持或完成联合兼容。

2026-11-02 至 2026-11-03 在本地用 Nacos 3.1.1 完成 Gateway 和 8 个服务的 `spring.config.import` 配置导入、gRPC 服务注册和实例查询，并通过 Gateway 的 `lb://` 路由访问账户服务；Valkey/RocketMQ 分别完成基础读写/消息往返。另在开发服务器上完成 OceanBase 4.4.2.1 MySQL 模式下的基础 SQL 检查及 Flyway 13.12.0 空库迁移。以上结果证明当前环境中的窄范围运行链路可工作，不覆盖完整应用集成、故障/安全/容量场景，也不替代供应商对框架 BOM 的正式支持依据。

## 决策

- 暂时保留仓库当前框架版本，不自行修改 POM。
- 等待供应商提供 Spring Cloud Alibaba 2025.1.0.0 对 Spring Boot 4.1.2、Spring Cloud 2025.1.4 的正式兼容依据，明确支持范围和已知限制。
- 九个应用的 Nacos dev 配置导入/注册及一条 Gateway 服务发现路由已通过；兼容状态仍因缺少供应商正式依据及完整故障、安全、容量验证而维持“未验证”，不得把阶段 0 任务 5 标记完成。
- 如供应商无法提供支持依据，重新评审版本组合；不得仅以依赖解析成功或基础启动成功替代该决策。

## 备选方案

- 立即改为官方版本说明列出的 Spring Boot 4.0.0 / Spring Cloud 2025.1.0：可与当前 Alibaba 对应表保持一致，但当前项目基线选择先保留已有版本，故暂不执行。
- 保留当前版本并直接宣称兼容：缺少依据，拒绝此做法；当前状态继续标记为未验证。
- 保留当前版本并等待供应商正式说明，之后执行联合验证：采用此临时方案。

## 后果

- 保持当前工程版本，避免在兼容性依据尚不完整时改变开发基线。
- 依赖 Alibaba 组合的阶段 1 平台集成仍受阶段 0 版本验证门禁约束。
- 供应商书面依据和联合验证报告成为阶段 0 任务 5 的必需证据。

## 复审条件

- 供应商发布或提供该版本组合的正式兼容说明时复审。
- Nacos/服务发现联合验证失败、供应商提交正式兼容依据，或官方发布新的兼容版本矩阵时立即复审。
