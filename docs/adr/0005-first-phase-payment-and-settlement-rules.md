# ADR-0005：首期支付渠道与清结算规则

**状态**：项目业务规则已确认；渠道合同和聚合服务能力待验证
**日期**：2026-11-03

## 背景

首期需支持实体校园卡消费、充值、退款/冲正和报表。支付回调、账单和结算由外部渠道/聚合服务提供，必须避免其账单状态与账户账本、交易流水脱节。

## 决策

1. 首期支付方式为实体校园卡，以及微信、支付宝、云闪付聚合支付。门禁和核验不属于首期，作为二期扩展。
2. 退款按原支付路径退回；冲正请求的业务目标时限为 24 小时。部分成功、超时、无法原路退回等行为仍按签约渠道契约定义。
3. 目标采用 T+1 自动对账；支付通道结算周期按已签约通道支持的 T+0/T+1 配置。
4. 交易类型比例验收边界为消费不少于 90%、充值/补助不多于 8%、退款/冲正少于 2%。具体负载样本及残余类别须从业务台账/接口契约确认。
5. 支付适配服务拥有渠道请求/回调标准化状态；清结算服务拥有渠道账单对账、批次、清分和差错状态；账户服务是余额/账本唯一写入权威，结算结果通过账户契约幂等提交。
6. 渠道验签、重放保护、回调去重、超时查询、退款幂等、账单时区/节假日及人工差错权限必须按最终聚合服务合同和沙箱协议验证；不能因采用“聚合支付”推断通道统一具有这些能力。

## 备选方案

- 首期只支持实体校园卡：接入面较小，但不满足已确认的移动支付范围；不采用。
- 各移动支付渠道分别直连接入：可独立控制回调和结算，但需要分别承担多套商户合同与协议集成；本项目选择聚合支付方向，具体产品待合同确认。
- 由清结算直接修改账户余额：实现批次可能较直接，但破坏账户服务作为账本权威的边界；不采用。

## 后果

- 首期业务范围和资金方向已可用于接口契约草案；渠道产品、商户号、费率、限额、回调规范和结算时间仍不能冻结。
- T+1 自动对账与 T+0/T+1 结算是项目目标输入，不代表所有渠道合同都支持相同账期。
- 渠道合同或沙箱与本 ADR 冲突时，先记录差异并复审本 ADR；不得悄然改变账户账本语义。

## 复审条件

取得校园卡产品和聚合支付服务的正式合同、商户后台配置及沙箱资料后，补齐逐渠道状态机、验签/重放、退款、对账和结算测试。

## 依据

首期范围、支付方式、T+1 自动对账、原路退款、24 小时冲正和 T+0/T+1 结算均为 2026-11-03 用户确认的项目输入；不是对所有支付产品能力或行业法规的外部结论。
