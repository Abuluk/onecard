# 阶段 0：业务基线、架构决策与技术验证详细方案

**状态**：阶段 0 临时开发基线结项；真实渠道/设备/生产证据按门禁跟踪
**目标**：把业务边界、架构决策、目标技术组合、容量和安全要求变为有证据、可执行的基线
**范围**：调研、ADR、模型/契约草案、目标组合 PoC、故障与性能基准
**不含**：账户/交易/门禁等生产业务功能实现

本方案细化 `docs/开发阶段规划.md` 中的阶段 0。阶段 0 形成决策、开发基线和已有 PoC 证据；按临时验收边界，阶段 1 可在 fail-closed 和模拟依赖约束下建设工程与运行平台。生产收款、离线消费、公开受保护 API 和生产 HA 故障切换须各自先满足门禁。

本轮用户授权对缺失输入先拟定默认方案并继续推进，方案与后续审阅项集中记录于 [`docs/阶段0-待确认事项与暂定方案.md`](../docs/阶段0-待确认事项与暂定方案.md)。暂定方案允许受限阶段 1 开发；不代替真实渠道、设备、合规或 HA 故障注入证据。

**临时验收解释（2026-11-04）**：用户要求缺失项先采用暂行方案并完成阶段 0。自本次修订起，本计划复选框代表该任务已完成处置：已有结论/证据，或已指定暂行默认、禁止事项及后续门禁。标注“转阶段 1/生产门禁”的项目不代表真实验证已经通过；其证据状态继续记录在阶段 0 阻断点矩阵，阶段 0 临时结项不构成生产、渠道或合规批准。

## 1. 成功标准

- 一卡通业务流程、数据权属、资金状态机、在线优先/断线故障切换语义和异常终态均有明确记录。
- 每项架构选择都有 ADR，包含候选方案、依据、代价、失败策略、验证结果和复审条件；未决项明确标记阻断范围。
- 阶段 0 开发基线所需的 Spring/Alibaba、Nacos、数据库、缓存、消息和监控组合有文档依据及本地/开发服务器可复测结果；目标生产 OS/CPU/JDK 发行版适配明确延期，不声称已验证。
- 以真实业务数量和峰值窗口建立负载模型；当前先记录本地机器与 16 GB 开发服务器的测试容量基线。生产逐服务 SLO、最大业务规模和生产资源预算在生产目标环境确定后复核，不编造 TPS 或将开发测试结果外推。
- 威胁模型、数据分类、身份/网络边界、合规适用性和门禁生命安全行为有可复核的结论或验证计划。
- 阶段 0 验收包足以让阶段 1 按固定基线实施，不需要在阶段 1 临时猜测关键架构决定。

## 2. 当前基线与已知风险

- 当前 Maven 基线按 Spring Cloud Alibaba 官方版本表对齐为 JDK 25、Spring Boot 4.0.0、Spring Cloud 2025.1.0、Spring Cloud Alibaba 2025.1.0.0；生产适用性仍待目标环境验证。
- Nacos、OceanBase、Valkey、RocketMQ 尚未组成持久化业务运行栈。本地已对 Nacos 3.1.1、Valkey 9.1.3、RocketMQ 5.3.1 做隔离 PoC；OceanBase 4.4.2-lts 与 Flyway 13.12.0 已在开发服务器完成基础 SQL/迁移 PoC。本地 MySQL/Redis 仅用于 N9E，不能代表业务数据库/缓存验证结果。
- 在线交易是默认模式；仅意外断线触发终端有界故障切换。余额不足、卡冻结、风控拒绝等业务拒绝不得触发离线支付。已发出但结果未知的在途交易保持待确认，不转成本地成功；恢复后用同一幂等键查询/重试；后续新交易才可在故障切换状态下使用新序号进入离线流程。
- 账户账本归账户服务；交易服务负责编排；跨来源和日终对账归清结算服务。终端已确认、平台风控拒绝或不可用时的资金处理尚需明确。
- 当前 Gateway 默认配置了八个服务路径，设备和风控入口的实际信任边界仍需用暴露矩阵和网络图确定。
- 仓库所有者确认该仓库为私人仓库，并接受现有部署凭据的处理方式；按所有者决定，凭据吊销、历史改写等事件处置不属于本阶段任务。发布 workflow 的构建目录等工程问题仍可在阶段 1 CI 任务中处理。
- 当前本地开发机为 Windows 11 x64、Ryzen 7 5800H、约 15.86 GiB 可见内存。shell 的 `java` 命令报告 Temurin 25.0.5；Maven Wrapper 设置 `JAVA_HOME` 后实际使用 Oracle JDK 25.0.4.1，PoC 必须记录实际 Maven JVM。
- 用户指定一台 16 GB 内存开发测试服务器，策略为本地测试通过后再部署服务器复测。服务器访问信息仅用于执行，不写入版本控制文档；真实生产服务器预计更大，开发环境测试结果不代表生产容量。

## 3. 决策范围与顺序

| 顺序 | 决策域 | 必须回答的问题 | 主要产物 |
|---|---|---|---|
| 0 | 凭据处理范围 | 仓库所有者确认私人仓库并接受现有处理方式；凭据事件处置豁免，其他流水线工程问题另行维护 | 所有者接受结论（本阶段不处理凭据） |
| 1 | 业务范围与规模 | 有哪些用户、卡、终端、控制器、渠道、场景、峰值和日结要求 | 需求/容量输入表、系统上下文图 |
| 2 | 资金与离线状态 | 在线结果、断线、结果未知、风险拒绝、补传、入账、待复核和冲正如何转换 | 交易状态机、账务影响表、资金 ADR |
| 3 | 人员、门禁与身份 | 主数据源、撤销时限、身份源、设备认证、门型与消防行为如何定义 | 数据权属矩阵、身份/门禁 ADR |
| 4 | 安全与合规范围 | 系统边界、数据类别、威胁、审计/留存、合规适用范围是什么 | 数据分类、威胁模型、适用性结论 |
| 5 | 技术兼容与运行拓扑 | 目标版本/产品、网络、配置、密钥、存储与部署如何组合 | 兼容矩阵、部署图、组件 ADR |
| 6 | 容量、可靠性与恢复 | 吞吐、延迟、积压、恢复、RTO/RPO 和资源目标是多少 | 负载模型、SLO、备份/恢复目标 |
| 7 | 联合 PoC 与复核 | 目标组合是否满足功能、安全、兼容和容量底线 | PoC、故障/性能报告、阶段退出评审 |

顺序 1-6 可并行调研，但决策依赖要显式记录；资金状态、人员数据权属、身份边界、目标技术组合和容量输入未定时，不得宣称阶段 0 完成。

## 4. 详细任务

### 任务 0：凭据处置范围确认（已豁免）

**目标**：按仓库所有者指示记录该事项的处理范围，避免把已接受的私人仓库凭据事件误列为阶段 0 阻断项。

**验收条件**：

- [x] 仓库所有者确认仓库为私人仓库，并明确本阶段不需要对现有凭据做额外处理。
- [x] 凭据吊销、轮换和 Git 历史改写不列入本阶段交付；是否改变此决定由仓库所有者重新提出。
- [x] 发布 workflow 指向无效构建路径的问题保留为阶段 1 CI 工程事项，不与凭据处置混为一个风险门。

**验证**：以本次用户确认作为范围记录；不执行凭据轮换或远端历史改写。

**依赖**：无。
**产物**：所有者确认的范围记录。
**规模**：小；已完成。

### 任务 1：业务范围、用户和规模输入

**目标**：获得建模和容量估算所需的真实业务输入，并区分已知事实、假设和待补数据。

**验收条件**：

- [x] 记录首期消费、充值、退款/冲正、报表必选，门禁/核验二期扩展；确认聚合充值入校园卡账户、校园卡余额刷卡消费为主、聚合渠道也可直接消费三条资金路径，见 ADR-0005/0007。
- [x] 收集并区分已知设计输入与待核实台账/合同：8,000 人、4 个站点、单站点 800 笔/分钟、交易类型比例和留存策略已记录；旧 16,000 笔/日输入已作废，以 96,000 笔/30 分钟为新压力目标。约 150 台终端仅为规划估算；实际日分布、消息量、日结量、增长率及渠道限额明确转数据/合同门禁，不虚构预测。
- [x] 绘制首版系统上下文和外部依赖图，标明用户/管理角色、支付渠道、设备、人员主数据、内部资金/清算链路和待确认外部系统。
- [x] 区分已确认事实、暂定设计、厂商能力声明和待验证数据；实际台账/合同与终端资产仍待补，后续容量/合规结论必须引用对应证据。

**验证**：流程、用户输入、设计场景和待核实项分开记录；取得正式台账后再复核日交易量和峰值场景。当前不再使用旧的 5%–10%集中度推算。

**依赖**：任务 0 可并行。
**产物**：[`docs/阶段0-业务范围与规模输入.md`](../docs/阶段0-业务范围与规模输入.md)、[`docs/architecture.md`](../docs/architecture.md) 首版上下文图、业务范围说明、用户/设备清单、容量输入表、待确认项表。
**规模**：中。

### 任务 2：资金模型、交易状态机与终端故障切换决策

**目标**：冻结在线交易和终端断线故障切换的资金语义，避免交易、账户和终端各自实现不同规则。

**验收条件**：

- [x] 记录项目已确认的业务模式方向：在线为默认，只有确认的意外断线才由终端故障切换到离线支付；账户余额/账本本地原子提交与跨服务稳定幂等推进方向见 ADR-0008。
- [x] 选定开发基线方向：账户本地原子账务、稳定幂等操作标识、交易服务先持久化状态、账户查询/重试、outbox 至少一次推进；详见 ADR-0008。
- [x] 暂定幂等保留与重复语义：资金来源键与账务记录同生命周期、项目策略为在线 5 年加归档 10 年；同键同摘要返回首次结果，同键不同摘要冲突。账户提交后丢响应、服务重启、消息重复/乱序故障测试仍待做。
- [x] 写清在线默认和 PoC 断线触发值（5 秒内连续 3 次传输层失败）；余额不足、卡冻结、风控拒绝等业务响应不得触发本地支付；当前未知在途交易待确认，后续新交易才能进入离线故障切换。阈值待设备联测。
- [x] 暂定离线单笔/日限额均配置化且缺省为零/关闭，名单/额度租约 PoC 最长 3 个就餐日；终端撤销/丢失、序号回退、时钟偏移、WAL 损坏/存储耗尽的行为需设备方案和故障测试验证。
- [x] 明确 `NEED_REVIEW` 进入待处理状态并保留离线额度；审核通过后记账，审核拒绝走可审计补偿/冲正，见 ADR-0003。
- [x] 定义恢复屏障顺序：查询未知在线请求、按终端序号幂等补传、确认连续高水位、同步账户余额/预留额后恢复在线；屏障证明仍待设备/账务故障测试。
- [x] 固定 `(tenant_id, terminal_id, local_seq_no)` 作为离线来源唯一键，64 位序号需先持久化；重复相同摘要返回原结果，冲突载荷告警/人工处理，缺号暂存等待补齐、乱序不改变账务顺序。端侧持久化与服务端唯一索引测试仍待做。

**验证**：用状态转移表和可执行状态机/模拟器覆盖业务拒绝、请求未发送、服务端已提交但响应丢失、服务端拒绝但响应丢失、断线抖动、后续新交易离线受理、重复补传、风控不可用、恢复同步和重复请求；对每条路径核对交易状态、账户分录、终端提示与客户资金影响。

**依赖**：任务 1。
**产物**：[`docs/adr/0001-online-first-terminal-failover.md`](../docs/adr/0001-online-first-terminal-failover.md)、[`docs/adr/0003-offline-payment-reserve-and-review.md`](../docs/adr/0003-offline-payment-reserve-and-review.md)、[`docs/阶段0-交易状态与账务影响矩阵.md`](../docs/阶段0-交易状态与账务影响矩阵.md)、幂等契约、恢复屏障测试报告。
**规模**：大；按在线状态机、离线状态机、恢复屏障三个评审切片完成。

### 任务 3：支付渠道、清结算与跨服务责任

**目标**：确认外部渠道状态如何进入交易/账本，并保持服务数据权属一致。

**验收条件**：

- [x] 从现有服务设计整理数据写入责任和调用方向初稿；渠道回调、可靠推进、清算结果和通知事件契约仍标为待决策。
- [x] 定义资金路径方向：聚合充值成功后幂等入账户、校园卡余额消费只改账户账本、聚合直付消费不增加校园卡余额；分路径退款/冲正和对账见 ADR-0005/0007 与交易账务矩阵。渠道级验签/重放、超时、部分成功和账单契约仍待合同/沙箱验证。
- [x] 真实渠道沙箱/支付宝云验收因合同和商户资料缺失转真实通道启用门禁；阶段 1 暂用供应商中立契约和本地模拟渠道，不发起真实资金请求。所需真实材料见[证据矩阵](../docs/阶段0-阻断点关闭证据矩阵.md)。
- [x] 明确账户账本、交易流水、终端本地流水、支付渠道账单和清结算结果的服务写入边界；清结算只经账户服务契约提交结果，不直接改账户余额。
- [x] 明确交易、账户、支付适配和通知之间调用/事件边界，选用本地事务 + outbox + 至少一次投递、消费者幂等去重与状态查询/补偿；真实客户端和依赖故障测试转阶段 1 门禁。
- [x] 暂定跨服务操作 ID、离线来源键、事件 ID、15 年项目引用保留、退避重试和人工告警队列；事件 schema 版本及人工差错权限在 API 契约评审冻结。

**验证**：以表格逐项模拟渠道成功/拒绝/超时、重复/乱序回调、退款部分成功、账户已提交而调用方超时、消息重复和日终对账；验证所有路径有收敛状态和明确的服务数据边界。

**依赖**：任务 1、2。
**产物**：[`docs/阶段0-跨服务责任矩阵.md`](../docs/阶段0-跨服务责任矩阵.md)、跨服务调用/事件图、渠道与清结算状态表、ADR。
**规模**：中。

### 任务 4：人员主数据、身份、安全、隐私与门禁生命安全

**目标**：定义谁能访问哪些入口、设备如何被信任、个人信息如何被处理，以及离线门禁的安全边界。

**验收条件**：

- [x] 汇总当前 API/设备/管理/内部信任边界、已配置 Gateway 路径、生物特征待确认范围和候选数据类别；初稿不作正式数据等级或合规结论。
- [x] 暂定学校学籍/人事/卡务系统为权威源，一卡通只读同步并用稳定外部 ID 映射；实际系统、撤权 SLA 与冲突流程列阶段 1 上游接入门禁；门禁服务不成为主数据源。
- [x] 记录用户/管理员身份协议选择为 OIDC；用户确认 `https://xxx` 是脱敏占位，并选择 Keycloak 默认 `realm_access.roles` 字符串数组作为 claim 路径。
- [x] 隔离 Keycloak 26.8.1 PoC 确认 discovery、access token issuer 和 realm role 数组；PoC 默认 audience `account` 不作为业务 API audience。
- [x] 暂定 Keycloak 开发模板 `fullScopeAllowed=false`、`ENFORCING`、最小角色范围；资源服务器配置导出、授权矩阵及无效签名/issuer/audience/过期/角色不足五条负向用例设为任何受保护 API 对外开放前的门禁，见[关闭证据矩阵](../docs/阶段0-阻断点关闭证据矩阵.md)。
- [x] 记录本地 OIDC 测试模板：Keycloak issuer 示例、`onecard-api` audience、`onecard-user`/`onecard-admin`/`onecard-auditor` 角色及最小权限；正式 issuer/角色矩阵、服务/设备凭证生命周期、职责分离、密钥保管和轮换仍待校方/环境资料。
- [x] 记录门禁与核验是二期扩展；一期不启用该入口。真实控制器断电/断网、撤权、消防与疏散测试须在二期设备选型和现场条件具备后、二期开发前完成。
- [x] 路由暴露矩阵暂定 Gateway 为普通用户唯一入口，回调/设备/内部/运维分开授权；服务直连、Nacos 管理面、Actuator 默认私网/拒绝。目标环境 CIDR 和防火墙规则在部署门禁中填实。

## 6. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 把候选组件当作已批准生产栈 | 版本/信创/安全不兼容，造成后续返工 | 官方资料与目标环境联合验证后才进入兼容矩阵的“通过”列 |
| 需求规模数据缺失 | SLO 和成本随意设定 | 标记缺口、对设计的影响和恢复条件；未核实数字不得作为生产容量结论 |
| 资金异常状态定义不清 | 重复扣款、账实不平或线下纠纷 | 状态转移和账户影响逐项评审并故障注入 |
| 门禁通用 fail-closed 决策 | 影响消防与紧急疏散 | 按实际门型、设备能力和现场消防联动验证，不以通用策略替代 |
| 合规结论超出证据 | 方案误导采购/测评 | 记录适用性与证据来源；正式结论需后续专业评估，不在本阶段臆定 |
| 私人仓库现有凭据处理方式 | 仓库所有者认为当前方式可接受 | 记录所有者决定；如仓库可见性、凭据权限或所有者意见变化，重新评估 |
| 生产 OS/CPU/JDK 发行版暂不可用 | 生产联合兼容无法提前确认 | 当前开发基线先推进；生产部署前必须取得目标环境并完成适配验证 |
| 16 GB 开发服务器被误作生产容量证明 | 线上容量和成本判断偏差 | 报告标注开发环境；生产资源更换后按业务负载重测 |
| PoC 只验证单组件 | 联合运行仍失败 | 对锁定版本、OS/JDK、数据库/缓存/消息执行端到端组合验证 |
