# 阶段 0：业务基线、架构决策与技术验证详细方案

**状态**：进行中；当前优先阶段
**目标**：把业务边界、架构决策、目标技术组合、容量和安全要求变为有证据、可执行的基线
**范围**：调研、ADR、模型/契约草案、目标组合 PoC、故障与性能基准
**不含**：账户/交易/门禁等生产业务功能实现

本方案细化 `docs/开发阶段规划.md` 中的阶段 0。阶段 0 和阶段 1 是两个独立、顺序执行的阶段：阶段 0 产出决策与验证证据；阶段 1 才建设工程与运行平台。阶段 0 未通过前，不开始阶段 1 中依赖未决身份、组件、数据或 SLO 的实现。

## 1. 成功标准

- 一卡通业务流程、数据权属、资金状态机、在线优先/断线故障切换语义和异常终态均有明确记录。
- 每项架构选择都有 ADR，包含候选方案、依据、代价、失败策略、验证结果和复审条件；未决项明确标记阻断范围。
- 阶段 0 开发基线所需的 Spring/Alibaba、Nacos、数据库、缓存、消息和监控组合有文档依据及本地/开发服务器可复测结果；目标生产 OS/CPU/JDK 发行版适配明确延期，不声称已验证。
- 以真实业务数量和峰值窗口建立负载模型；当前先记录本地机器与 16 GB 开发服务器的测试容量基线。生产逐服务 SLO、最大业务规模和生产资源预算在生产目标环境确定后复核，不编造 TPS 或将开发测试结果外推。
- 威胁模型、数据分类、身份/网络边界、合规适用性和门禁生命安全行为有可复核的结论或验证计划。
- 阶段 0 验收包足以让阶段 1 按固定基线实施，不需要在阶段 1 临时猜测关键架构决定。

## 2. 当前基线与已知风险

- 当前 Maven 基线为 JDK 25、Spring Boot 4.1.2、Spring Cloud 2025.1.4、Spring Cloud Alibaba 2025.1.0.0；目标运行兼容性和生产适用性仍待核实。
- Nacos、OceanBase、Valkey、RocketMQ 等目标组件尚未组成业务运行栈。本地 MySQL/Redis 仅用于 N9E，不能代表业务数据库/缓存验证结果。
- 在线交易是默认模式；仅意外断线触发终端有界故障切换。余额不足、卡冻结、风控拒绝等业务拒绝不得触发离线支付。已发出但结果未知的在途交易保持待确认，不转成本地成功；恢复后用同一幂等键查询/重试；后续新交易才可在故障切换状态下使用新序号进入离线流程。
- 账户账本归账户服务；交易服务负责编排；跨来源和日终对账归清结算服务。终端已确认、平台风控拒绝或不可用时的资金处理尚需明确。
- 当前 Gateway 默认配置了八个服务路径，设备和风控入口的实际信任边界仍需用暴露矩阵和网络图确定。
- 仓库所有者确认该仓库为私人仓库，并接受现有部署凭据的处理方式；按所有者决定，凭据吊销、历史改写等事件处置不属于本阶段任务。发布 workflow 的构建目录等工程问题仍可在阶段 1 CI 任务中处理。
- 当前本地开发机为 Windows 11 x64、Ryzen 7 5800H、约 15.86 GiB 可见内存。shell 的 `java` 命令报告 Temurin 25.0.5；Maven Wrapper 设置 `JAVA_HOME` 后实际使用 Oracle JDK 25.0.4.1，PoC 必须记录实际 Maven JVM。
- 用户指定一台 16 GB 内存开发测试服务器，策略为本地测试通过后再部署服务器复测。服务器访问信息仅用于执行，不写入版本控制文档；真实生产服务器预计更大，开发环境测试结果不代表生产容量。

## 3. 决策范围与顺序

| 顺序 | 决策域 | 必须回答的问题 | 主要产物 |
|---|---|---|---|
| 0 | 凭据处理范围 | 仓库所有者确认私人仓库并接受现有处理方式；凭据事件处置豁免，其他流水线工程问题另行维护 | 所有者接受结论（本阶段不处理凭据） |
| 1 | 业务范围与规模 | 有哪些用户、卡、终端、控制器、渠道、场景、峰值和日结要求 | 需求/容量输入表、系统上下文图 |
| 2 | 资金与离线状态 | 在线结果、断线、结果未知、风险拒绝、补传、入账、待复核和冲正如何转换 | 交易状态机、账务影响表、资金 ADR |
| 3 | 人员、门禁与身份 | 主数据源、撤销时限、身份源、设备认证、门型与消防行为如何定义 | 数据权属矩阵、身份/门禁 ADR |
| 4 | 安全与合规范围 | 系统边界、数据类别、威胁、审计/留存、合规适用范围是什么 | 数据分类、威胁模型、适用性结论 |
| 5 | 技术兼容与运行拓扑 | 目标版本/产品、网络、配置、密钥、存储与部署如何组合 | 兼容矩阵、部署图、组件 ADR |
| 6 | 容量、可靠性与恢复 | 吞吐、延迟、积压、恢复、RTO/RPO 和资源目标是多少 | 负载模型、SLO、备份/恢复目标 |
| 7 | 联合 PoC 与复核 | 目标组合是否满足功能、安全、兼容和容量底线 | PoC、故障/性能报告、阶段退出评审 |

顺序 1-6 可并行调研，但决策依赖要显式记录；资金状态、人员数据权属、身份边界、目标技术组合和容量输入未定时，不得宣称阶段 0 完成。

## 4. 详细任务

### 任务 0：凭据处置范围确认（已豁免）

**目标**：按仓库所有者指示记录该事项的处理范围，避免把已接受的私人仓库凭据事件误列为阶段 0 阻断项。

**验收条件**：

- [x] 仓库所有者确认仓库为私人仓库，并明确本阶段不需要对现有凭据做额外处理。
- [x] 凭据吊销、轮换和 Git 历史改写不列入本阶段交付；是否改变此决定由仓库所有者重新提出。
- [x] 发布 workflow 指向无效构建路径的问题保留为阶段 1 CI 工程事项，不与凭据处置混为一个风险门。

**验证**：以本次用户确认作为范围记录；不执行凭据轮换或远端历史改写。

**依赖**：无。
**产物**：所有者确认的范围记录。
**规模**：小；已完成。

### 任务 1：业务范围、用户和规模输入

**目标**：获得建模和容量估算所需的真实业务输入，并区分已知事实、假设和待补数据。

**验收条件**：

- [ ] 梳理消费、充值、退款/冲正、门禁、核验、清分和报表的目标/非目标，以及用户、管理员、财务、运维和设备等使用场景。
- [ ] 收集当前与规划用户数、卡数、终端/控制器数量、食堂峰值时段、在线交易峰值、支付渠道限额、消息事件量、日结数据量、留存期和业务增长假设；未知数据保留待补状态及其对设计的影响。
- [x] 绘制首版系统上下文和外部依赖图，标明用户/管理角色、支付渠道、设备、人员主数据、内部资金/清算链路和待确认外部系统。
- [ ] 区分已确认事实、业务假设、厂商能力声明和待验证数据，后续容量/合规结论引用对应证据。

**验证**：流程、数据来源和假设记录可复核；规模输入按已提供的统计窗口和集中度估算口径记录。若后续取得台账，再交叉核验峰值小时总量与 1 分钟滑动窗口估算。

**依赖**：任务 0 可并行。
**产物**：[`docs/阶段0-业务范围与规模输入.md`](../docs/阶段0-业务范围与规模输入.md)、[`docs/architecture.md`](../docs/architecture.md) 首版上下文图、业务范围说明、用户/设备清单、容量输入表、待确认项表。
**规模**：中。

### 任务 2：资金模型、交易状态机与终端故障切换决策

**目标**：冻结在线交易和终端断线故障切换的资金语义，避免交易、账户和终端各自实现不同规则。

**验收条件**：

- [x] 记录项目已确认的业务模式方向：在线为默认，只有确认的意外断线才由终端故障切换到离线支付。
- [ ] 明确账户服务本地事务内的余额与账本不变量、交易服务状态机、账户写入可靠推进机制、超时/重复/服务重启/未知结果查询与幂等保留期限；在 outbox、幂等状态机等候选中作出有证据的选择。
- [ ] 写清在线默认、意外断线判定阈值/连续失败数/恢复观察期/防抖；余额不足、卡冻结、风控拒绝等业务响应不得触发本地支付；当前未知在途交易待确认，后续新交易才能进入离线故障切换。
- [ ] 决定每卡/每终端离线额度、最长断线时间、状态缓存新鲜度、终端撤销/丢失、序号回退、时钟偏移、WAL 损坏/存储耗尽的行为。
- [x] 明确 `NEED_REVIEW` 进入待处理状态并保留离线额度；审核通过后记账，审核拒绝走可审计补偿/冲正，见 ADR-0003。
- [ ] 定义恢复屏障：本地流水同步、幂等确认、账户入账/保留额、余额刷新和终端恢复普通在线模式的顺序与确认条件，证明不会重复开放余额。
- [ ] 固定 `terminal_id + local_seq_no` 等幂等键组成、唯一范围、序号持久化、重复/缺口/乱序处理及离线流水重放策略。

**验证**：用状态转移表和可执行状态机/模拟器覆盖业务拒绝、请求未发送、服务端已提交但响应丢失、服务端拒绝但响应丢失、断线抖动、后续新交易离线受理、重复补传、风控不可用、恢复同步和重复请求；对每条路径核对交易状态、账户分录、终端提示与客户资金影响。

**依赖**：任务 1。
**产物**：[`docs/adr/0001-online-first-terminal-failover.md`](../docs/adr/0001-online-first-terminal-failover.md)、[`docs/adr/0003-offline-payment-reserve-and-review.md`](../docs/adr/0003-offline-payment-reserve-and-review.md)、[`docs/阶段0-交易状态与账务影响矩阵.md`](../docs/阶段0-交易状态与账务影响矩阵.md)、幂等契约、恢复屏障测试报告。
**规模**：大；按在线状态机、离线状态机、恢复屏障三个评审切片完成。

### 任务 3：支付渠道、清结算与跨服务责任

**目标**：确认外部渠道状态如何进入交易/账本，并保持服务数据权属一致。

**验收条件**：

- [x] 从现有服务设计整理数据写入责任和调用方向初稿；渠道回调、可靠推进、清算结果和通知事件契约仍标为待决策。
- [ ] 确定支付渠道请求、回调验签/重放保护、超时查询、部分成功、退款/撤销、渠道对账数据和账户入账之间的状态与幂等关系。
- [ ] 明确账户账本、交易流水、终端本地流水、支付渠道账单和清结算结果的服务写入边界；清结算只经账户服务契约提交结果，不直接改账户余额。
- [ ] 明确交易、账户、支付适配和通知之间调用/事件边界，选择可靠消息/outbox/查询补偿等推进方式，并定义至少一次投递、去重与重放行为。
- [ ] 明确跨服务业务 ID、幂等键、事件版本、状态保留期、重试/死信和人工差错流程。

**验证**：以表格逐项模拟渠道成功/拒绝/超时、重复/乱序回调、退款部分成功、账户已提交而调用方超时、消息重复和日终对账；验证所有路径有收敛状态和明确的服务数据边界。

**依赖**：任务 1、2。
**产物**：[`docs/阶段0-跨服务责任矩阵.md`](../docs/阶段0-跨服务责任矩阵.md)、跨服务调用/事件图、渠道与清结算状态表、ADR。
**规模**：中。

### 任务 4：人员主数据、身份、安全、隐私与门禁生命安全

**目标**：定义谁能访问哪些入口、设备如何被信任、个人信息如何被处理，以及离线门禁的安全边界。

**验收条件**：

- [x] 汇总当前 API/设备/管理/内部信任边界、已配置 Gateway 路径、生物特征待确认范围和候选数据类别；初稿不作正式数据等级或合规结论。
- [ ] 确定人员/卡介质主数据权威源、同步方向、撤权时限、离线数据范围和冲突处理；门禁服务不成为未授权主数据源。
- [ ] 明确用户、管理员、服务和设备的身份提供方、凭证/证书生命周期、认证/授权模型、职责分离、服务间最小权限、密钥保管和轮换。
- [ ] 形成外部路由暴露矩阵，区分用户/管理、支付回调、设备协议、内部服务调用和运维管理；定出直连服务端口、网络分区、Nacos 管理面和 Actuator 的访问规则。
- [ ] 完成数据分类分级和数据流图；明确个人/生物特征/消费/通行数据的采集目的、最小化、日志脱敏、访问审计、留存/删除和备份策略，不默认采集或记录生物模板。
- [ ] 对系统定级、等保/密评、商用密码和产品认证作适用性分析，结论标注依据和待确认事项，不把工程方案文字视为正式测评结论。
- [ ] 按门型列明控制器断电/断网/快照过期/撤权/时钟错误/消防联动/紧急疏散时的预期动作和实测方案。
- [ ] 对支付回调、用户入口、服务间调用、设备命令、Nacos/数据库/消息和日志构建威胁模型及滥用场景。

**验证**：安全与现场行为结论有记录；在真实门型/控制器上验证消防及疏散行为计划，不以通用模拟器替代生命安全验证；抽样演练凭据撤销和人员撤权。

**依赖**：任务 1；与任务 2、3 并行。
**产物**：[`docs/阶段0-安全与数据边界初稿.md`](../docs/阶段0-安全与数据边界初稿.md)、身份/网络边界 ADR、路由矩阵、威胁模型、数据分类/权属表、合规适用性记录、门禁安全验收方案。
**规模**：大；身份、隐私/合规、现场门禁分开评审后汇总。

### 任务 6：负载模型、逐服务 SLO 和资源预算

**目标**：先建立本地与 16 GB 开发服务器上的可复测开发容量基线，并保留真实业务规模数据缺口；生产容量目标留待生产环境和业务规模确定后复核。

**验收条件**：

- [ ] 将已取得的业务输入转为请求类型和测试模型；未取得的用户、设备、峰值、增长和留存数据标成待补，不用臆造值填充。
- [x] 将用户提供的约 8,000 名发卡用户、约 150 台终端（其中约 100 台门禁）、约 200–800 笔/分钟高峰及约 16,000 笔/日记录为初始输入；这些数值未视为经台账核实或已批准的生产负载。
- [ ] 核对峰值适用范围（全平台/单站点）、交易类型比例和峰值小时交易量统计口径；按午餐高峰小时内 1 分钟滑动窗口及 5%–10%估算集中度建立负载曲线。该项无需填写单独负责人。
- [x] 记录本地机器 OS/JDK/CPU/内存/Docker 基线；本地先测的顺序已确认。
- [ ] 采集 16 GB 开发服务器 OS/JDK/CPU/内存/磁盘/Docker 和空闲资源；当前 SSH 端口连接超时，未进行远端变更。
- [ ] 对阶段 0/1 可测试的软件链路定义开发验证门槛及报告项；只报告实测吞吐、p50/p95/p99、错误率、资源消耗和故障恢复，不宣称生产 SLO 达标。
- [x] 将逐服务生产吞吐、p95/p99、错误率、资源上限列为延期项，待实际业务规模和目标生产环境确定后再核定。
- [ ] 为最长批准离线窗口和最大恢复积压建立模型；明确补传清空时间、在线消费保护阈值、公平性、超额度行为和积压告警阈值。
- [ ] 定义数据库容量/连接池、消息分区/保留、缓存命中与失效、监控基数/采样和日结批次时间的验收边界。
- [ ] 约定基准/稳态/峰值/突发/压力上限/长稳/故障降级/恢复补压的环境、数据、并发和报告格式；每个门槛有来源和测试结果。
- [ ] 明确 16 GB 开发服务器是阶段性测试基线；未来生产服务器更换后需重跑性能/容量测试，当前结果不外推到生产。

**验证**：当前非生产测试环境和报告格式已记录；有业务输入的场景按其来源核算。未提供的真实业务规模和生产 SLO 保持未决，不阻止开发基线测量但不能标记生产容量通过。

**依赖**：任务 1、5。
**产物**：[`docs/阶段0-负载模型与SLO.md`](../docs/阶段0-负载模型与SLO.md)、开发环境容量基线、已知/缺失的业务规模输入、阶段性测试矩阵、生产容量延期项。
**规模**：中；生产容量复核延期。

### 任务 7：目标环境联合 PoC、故障与性能验证

**目标**：证明选定组合可运行且满足阶段 0 的最低功能、安全和性能要求。

**验收条件**：

- [x] 本地完成 Maven 全量构建、现有自动化测试、Compose 文件解析，并记录 Maven 实际使用的 JDK。
- [x] 本地验证 `optional:nacos:` 配置源不可达且关闭注册时账户服务仍可启动并健康；记录客户端持续重试，该结果不代表 Nacos 配置加载或服务注册通过。
- [ ] 本地通过后，在用户指定的 16 GB 开发服务器复测；须先恢复 SSH 连通并采集远端环境，不能把本地结果当作服务器结果。
- [ ] 在当前本地/开发服务器环境中完成阶段 0 可用的 Spring/Cloud/Nacos 组合启动、配置导入、服务注册/发现和指标抓取；目标生产 OS/CPU/JDK 发行版联合测试延期。
- [ ] 用目标数据库验证 JDBC/ORM 方言、事务隔离、并发更新、迁移/恢复、审计/加密和连接池；用目标缓存验证一致性、过期、并发和节点故障；用目标消息验证 TLS、至少一次、重复/乱序、重放、积压和消费恢复。
- [ ] 对账户写入和交易推进候选方案做可丢响应、服务重启、重复幂等请求、消息重复及依赖故障试验；账务不变量保持成立。
- [ ] 对端侧状态机模拟网络延迟、丢包、意外断线、请求未知、业务拒绝、链路抖动、终端重启、恢复屏障和积压补传；证明业务拒绝不会触发本地支付，未知在途交易不被转成本地成功。

- [ ] 进行配置/权限/网络/密钥/镜像/依赖基础安全检查；门禁真实设备的生命安全验证方案按实际门型制定并留档。

**依赖**：任务 2-6 的开发基线决策已完成；任务 5 的生产 OS/CPU/JDK 发行版适配延期已记录；任务 6 的测试环境顺序已确认。

## 5. 检查点与阶段退出

### 检查点 A：业务、资金和数据责任（任务 1-3）

- [ ] 用户/设备/渠道范围和关键规模输入有来源，未知项已标明影响。
- [ ] 在线交易、未知结果、断线故障切换、离线复核、入账和恢复屏障状态机及资金影响矩阵已形成一致记录。
- [ ] 账户、交易、终端、渠道和清结算的数据/写入责任无冲突。

### 检查点 B：身份、安全和合规边界（任务 4）

- [ ] 用户/管理员/服务/设备身份和网络分区明确；路由暴露矩阵默认拒绝未批准入口。
- [ ] 数据分类、日志脱敏、审计/留存和隐私范围有结论或明确待验证项。
- [ ] 门禁消防/疏散及断网、断电、过期行为有真实设备验证计划。
- [ ] 等保/密评/产品认证适用性记录证据来源及专业机构确认路径。

### 检查点 C：开发技术基线、拓扑和容量（任务 5-6）

- [ ] 开发基线软件版本及组合兼容结果可查；未验证生产 OS/CPU/JDK 发行版仍标记延期，不写成生产已选型。
- [ ] 本地到 16 GB 开发服务器的部署/测试顺序、网络、配置/密钥、监控拓扑和资源记录方式已确认。
- [ ] 开发环境容量测试模型和报告项已明确；生产服务 SLO/资源预算与真实业务规模未批准前继续标记延期。

### 检查点 D：联合验证与复核（任务 7-8）

- [ ] 功能、兼容、故障、安全和性能报告可复现，失败项已关闭或正式阻断。
- [ ] ADR 与各项方案文档口径一致，阶段复核结论有记录。

**阶段 0 开发基线退出条件**：A-D 全部通过；9 项架构审阅结论均有决策记录及证据；阶段 1 所需身份、软件配置、网络、数据库开发基线、非生产测试环境和开发阶段门槛已冻结；当前开发环境联合验证有可复现证据。私人仓库凭据处置按已确认范围豁免；生产 OS/CPU/JDK 发行版适配及生产容量 SLO 明确延期并记录恢复条件。退出评审不要求填写个人/部门责任方或签字栏。满足以上条件可进入阶段 1 开发，不代表生产选型、生产容量或合规验收完成。

## 6. 风险与控制

| 风险 | 影响 | 控制方式 |
|---|---|---|
| 把候选组件当作已批准生产栈 | 版本/信创/安全不兼容，造成后续返工 | 官方资料与目标环境联合验证后才进入兼容矩阵的“通过”列 |
| 需求规模数据缺失 | SLO 和成本随意设定 | 标记缺口、对设计的影响和恢复条件；未核实数字不得作为生产容量结论 |
| 资金异常状态定义不清 | 重复扣款、账实不平或线下纠纷 | 状态转移和账户影响逐项评审并故障注入 |
| 门禁通用 fail-closed 决策 | 影响消防与紧急疏散 | 按实际门型、设备能力和现场消防联动验证，不以通用策略替代 |
| 合规结论超出证据 | 方案误导采购/测评 | 记录适用性与证据来源；正式结论需后续专业评估，不在本阶段臆定 |
| 私人仓库现有凭据处理方式 | 仓库所有者认为当前方式可接受 | 记录所有者决定；如仓库可见性、凭据权限或所有者意见变化，重新评估 |
| 生产 OS/CPU/JDK 发行版暂不可用 | 生产联合兼容无法提前确认 | 当前开发基线先推进；生产部署前必须取得目标环境并完成适配验证 |
| 16 GB 开发服务器被误作生产容量证明 | 线上容量和成本判断偏差 | 报告标注开发环境；生产资源更换后按业务负载重测 |
| PoC 只验证单组件 | 联合运行仍失败 | 对锁定版本、OS/JDK、数据库/缓存/消息执行端到端组合验证 |
