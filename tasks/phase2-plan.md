**状态**：未开始；阶段 1 退出评审尚未通过，不能开始阶段 2 的正式实现。  
**核对日期**：2026-11-12  
**范围**：账户/卡介质生命周期、余额、账户账务操作、预留额度原语、不可变分录、幂等、审计与账户 outbox。  
**依据**：[`docs/开发阶段规划.md`](../docs/开发阶段规划.md)、[ADR-0003](../docs/adr/0003-offline-payment-reserve-and-review.md)、[ADR-0007](../docs/adr/0007-campus-stored-value-and-aggregator-boundary.md)、[ADR-0008](../docs/adr/0008-idempotent-account-operations-and-reliable-progression.md)、[ADR-0011](../docs/adr/0011-account-database-ownership-and-flyway.md)。

本计划按当前仓库工作树和已落盘证据制定。阶段 2 的业务写 API 在进入批准的身份、数据库和故障验收前不得对用户或生产终端开放；OceanBase/Flyway 平台 smoke 不等于账户账务已验证。

## 1. 当前项目基线

- 根 Maven 工程已包含 `services/onecard-account-service` 和 `apis/onecard-account-api`。账户服务目前只有启动类、安全配置和 dev 探针，没有账户/卡务领域 API、业务实体/仓储或业务迁移；API 模块目前只有 Maven 配置和 README，没有 Java 契约。
- 账户服务已接入 JDBC、Flyway、OceanBase 连接配置、独立运行/迁移账号、OAuth2 resource server、统一错误处理和 Actuator。生产迁移目录没有 V1；`V1__migration_probe.sql` 位于测试资源目录，只用于迁移 smoke。
- ADR-0011 的双 schema 隔离、运行账号 DDL 拒绝、重复迁移、checksum 和失败迁移恢复 smoke 已有 OceanBase 证据；这些验证的是迁移/权限基线，不覆盖本阶段业务表、账务事务、并发或数据恢复。
- 账户服务当前业务请求要求 `onecard.account.invoke` scope；仅显式启用的 dev 配置探针是开发态例外。Gateway 开发态路由默认拒绝。正式用户/管理员与服务调用者矩阵、生产外部 API 暴露批准仍是阶段 1/生产启用门禁。
- 账户 API README 目前称 Flyway 迁移位于 `apis/onecard-account-api`，与 ADR-0011 及账户服务迁移说明指定的 `services/onecard-account-service/src/main/resources/db/migration` 冲突。业务迁移按 ADR-0011 放在服务模块；准入核对须同步修正文档，避免后续把迁移放进 API JAR。
- ADR-0008 已定义账户服务独占余额与账本、稳定 `operation_id`、同键摘要冲突、余额/分录/幂等结果/outbox 同库事务提交，以及 outbox 至少一次发布方向；这些是开发基线，不代表功能已有实现。
- 阶段 0 已记录校园卡储值、消费、充值和聚合直付的资金边界，以及离线预留与 `NEED_REVIEW` 的处理方向。金额精度/上限、具体账户与卡状态迁移、字段级数据分类和正式人员主数据源仍需在本阶段契约冻结时确认；不得把暂定规则写成生产批准。
- `tasks/phase1-todo.md` 中任务 0-8 已勾选，但检查点 A/B/C 和阶段 1 退出评审仍未勾选。因此阶段 2 依赖当前尚未完成，需先关闭阶段 1 退出检查；阶段 1 的性能报告是平台到 stub 的基线，不是账户业务容量结果。

## 2. 目标与边界

阶段完成时，账户服务能够安全维护账户、卡介质及其关联，查询余额和状态，并以可恢复、可审计、幂等的本地数据库事务执行已批准的资金变更。账户服务是余额与账本唯一写入方；其他服务只能经版本化 API/事件调用，不得共享表或直接写账户 schema。

本阶段包括校园卡账户余额入账、扣款、反向分录、账户/卡冻结与解冻，以及 ADR-0003 所需的额度预留/结清基础操作。额度策略、终端签发/同步、离线受理、实时风控和恢复屏障由阶段 3-6 完成；本阶段不启用生产离线额度。

本阶段不实现交易服务编排、真实聚合支付渠道、终端协议、人员主数据同步、清结算批次、门禁/核验、生物特征处理或生产 HA/容量承诺。聚合渠道直接消费不增加校园卡账户余额。

## 3. 开工门槛与设计约束

1. 阶段 1 退出评审通过，特别是与账户 API 相关的供应链扫描、数据库运行/迁移身份、服务调用授权、私网边界和 CI 验证项有结论。生产 API 路由和真实资金开放仍分别服从其自身启用门禁。
2. 契约冻结任务必须为金额精度/币种及范围、账户与卡状态迁移、卡号/账户标识、操作来源与反向操作、审计字段/留存、调用主体和每类接口 scope 形成有记录的结论。人员主数据源未确定时只接受外部稳定引用，不在本阶段同步或复制人员主档。
3. 账户、卡、余额、预留、分录、幂等结果、outbox 由账户服务拥有。不得在 Gateway、交易、支付或清结算模块增加账户数据库访问。
4. 金额不得使用二进制浮点。使用何种精确表示、币种及舍入/上限规则由任务 1 冻结；所有资金输入执行正数、精度和范围校验。
5. 账本分录不可更新或删除。更正、退款、撤销均新增引用原操作的反向/补偿分录；冻结、人工调整和卡片生命周期变更记录操作者、原因和结果。
6. `operation_id` 在首次提交前由调用方稳定生成；服务端计算规范化请求摘要。相同键、相同摘要返回首个已提交结果；相同键、不同摘要返回 HTTP 409。余额、分录、幂等结果和 outbox 必须在账户服务单一数据库事务内一起提交或回滚。
7. 所有业务路由保持默认拒绝，直连服务端口保持私网。接口实现和 OpenAPI 落盘不等于批准对外暴露。
8. OceanBase MySQL 模式是当前开发数据库基线。生产 V1 迁移按 ADR-0011 从空业务 schema 开始；已应用迁移不可修改。OceanBase DDL 失败可能部分提交，恢复按检查/修复流程执行，不假设自动回滚。

### 任务 3：交付账户/卡介质生命周期与余额查询

**目标**：实现不改变资金总额的基础业务切片。

**验收条件**：

- [ ] 按已批准状态机实现账户/卡创建或登记、关联、查询、冻结/解冻及终止/换卡；非法迁移、重复标识和并发状态竞争有明确拒绝结果。
- [ ] 余额响应明确区分账面、可用和预留金额；无账户、失效卡、冻结账户/卡及无权查询不会泄漏数据或返回伪成功。
- [ ] 需审计的状态变更持久化主体、操作、原因、时间、traceId 和结果；敏感卡/人员标识不进入普通日志或高基数指标。
- [ ] 控制器/服务仅使用账户服务仓储与本地事务；无跨服务直写和 Gateway 数据访问。

**验证**：先写生命周期/查询的单元与 API 集成测试；验证状态迁移、重复登记、权限拒绝、traceId 和审计记录；`.\mvnw.cmd -pl services/onecard-account-service -am test` 通过。

**依赖**：任务 1、2。
**涉及文件**：账户服务领域/持久层/API 与对应测试，最多按生命周期和查询拆分 PR。
**规模**：大，拆成卡务状态与账户查询两个可独立验收切片。

### 任务 4：交付幂等账务分录与余额变更

**目标**：让每次已确认的资金操作在一个账户服务事务中完整、唯一、可查询。

**验收条件**：

- [ ] 实现已批准的入账、扣款和反向/补偿操作；扣款/预留在账户或卡冻结、余额不足、金额非法时不得产生资金副作用。
- [ ] 一个数据库事务原子提交幂等结果、余额变化、不可变分录与对应 outbox 事件；事务中任一步失败都不得留下部分账务状态。
- [ ] 相同 `operation_id` 与相同规范化请求返回第一次提交结果；同键不同摘要返回 409；反向分录必须引用原操作，不能覆盖原分录。
- [ ] 余额并发更新使用经证明的锁/版本/条件更新策略，避免同一账户并发扣款透支；跨账户操作不产生不必要的全局串行化。
- [ ] 对账查询可由账务分录重算并与余额投影一致；仅账户服务有余额和账本写权限。

**验证**：先写金额边界、重复/冲突、同账户并发竞争、不同账户并发、事务回滚和反向分录测试；通过属性/对账断言验证余额守恒、借贷平衡和无重复副作用。用 OceanBase 实测并发和提交后响应丢失；确认重试可查询原结果。

**依赖**：任务 2、3。
**涉及文件**：账户账务服务、事务/DAO、API 实现、数据库集成与并发测试。
**规模**：大，拆成幂等提交、并发余额控制、反向分录三个连续切片。

### 任务 5：交付预留额度基础操作

**目标**：落实 ADR-0003 的账户端资金保护原语，供后续终端阶段调用。

**验收条件**：

- [ ] 实现预留、撤销/到期处置、按离线流水结清及复核通过/拒绝所需的账户端账务操作；每次状态变化与余额/分录/幂等/outbox 原子收敛。
- [ ] 多终端或并发请求不能重复占用同一可用余额；未结清或 `NEED_REVIEW` 资金不会自动释放；拒绝后的资金释放只经显式、可审计补偿规则。
- [ ] 预留额度与卡/终端/有效期/版本绑定，具体限额与终端分发策略不在本任务默认；未通过设备和生产启用门禁时额度默认关闭。
- [ ] 普通消费扣款、退款与预留结清之间不可重复扣减或重复释放；账面、可用、预留金额可逐笔对账。

**验证**：覆盖并发预留、超限/过期/撤销、重复结清、乱序输入、风控待复核、补偿失败恢复和账务守恒；真实终端断电/离线受理测试留给阶段 6，不以账户单测代替。

**依赖**：任务 1、2、4。
**涉及文件**：账户预留操作、迁移（仅必要的前向迁移）、契约及对应测试。
**规模**：中。

### 任务 6：outbox 投递、持久审计与故障恢复

**目标**：证明账户事务提交后事件可恢复推进，资金审计可追溯。

**验收条件**：

- [ ] outbox 事件有稳定 ID、版本、业务关联 ID、类型、发生时间和最小化载荷；不得包含访问令牌、完整卡号或不必要个人数据。
- [ ] 发布器在提交后异步至少一次发送；重复发送由稳定事件 ID 去重，发送失败按 ADR-0008 退避并持续可见，不删除或伪报成功。
- [ ] 进程在事务提交前后退出、broker 不可用/恢复、重复投递和发布器重启后，账务记录不变且 outbox 能继续收敛；死信/人工介入有明确查询与告警证据。
- [ ] 资金操作、管理变更和安全拒绝审计不可与普通日志混淆；访问控制、字段脱敏和项目留存策略有持久化验证。

**验证**：使用隔离 RocketMQ/OceanBase 环境做事务提交/响应丢失、broker 停止恢复、重复投递、重启和积压排空测试；核对发布次数可以大于一次但业务效果仅一次。记录适用的审计留存决定，不把项目留存输入表述为法定结论。

**依赖**：任务 2-4；事件契约依赖任务 1。
**涉及文件**：账户 outbox 发布器、审计存储、消息集成测试、运行配置/告警文档。
**规模**：大，拆成审计留痕和 outbox 发布/恢复两个切片。

**涉及文件**：`tests/performance/`、账户服务测试、`artifacts/` 阶段报告及必要运行文档。
